# The fetch ledger's per-URL "where is the body" sentence, split by whether that page's own fetch
# result is ACTUALLY present in the messages being sent this turn — not merely fetched at some point
# this session. `fetched_facts_sections.txt` (loop._format_fetches) used to append its `body_inline`
# ("Its body is in this conversation above") to EVERY successful no-structure fetch that was not
# spilled, unconditionally — even after the harness (or cria's own history compaction) had scrolled
# the actual tool result out of the window the coder receives. Measured (Rust P20,
# 20260924T052642-01a0d361): the planner fetched docs.rs/toml, crates.io/crates/toml and
# docs.rs/crate/toml/latest/source; the coder never fetched any of the three, yet its facts message
# told it all three bodies were "in this conversation above" on every turn. Campaign-wide: 1,821 such
# claims, 1,045 with no call to that URL anywhere in the body the coder actually received. The coder
# then recalled nonexistent APIs from memory instead of reading — the block it was told to trust said
# reading was unnecessary, the transcript already had it.
#
# The exact-repeat fetch gate is already visibility-aware (webfetch.set_visible / _FETCH_SEEN): it
# refuses a repeat ONLY while the identical result is still in the conversation, and allows it again
# once compaction elides that result. This file's `body_absent` line is that SAME visibility fact,
# said instead of the false one — never new advice, and never a re-fetch instruction beyond the
# plain, checkable fact that a re-fetch is not blocked.
#
# `fetched_facts_sections.txt` (`body_inline` / `body_at`) is unmodified: a live comparable battery
# is running and cria re-reads prompts/*.txt on every call, so an EXISTING prompt file used by that
# run cannot change under it. This file is new, and is read only by the visibility-aware branch of
# `loop._format_fetches`.
body_absent =  Its body is NOT in this conversation — fetching that URL again is not blocked and will return it.
# Appended to the durable anchor's closing tail (fetched_facts_sections.anchor_tail_fetches) ONLY when
# at least one entry in THIS render used `body_absent` above. The tail's "code against THOSE rather
# than re-fetching" names entries that list endpoints or response fields — never the ones carrying
# this note — but a reader skimming the whole block could still read it as covering every entry
# above it. This one clarifying sentence scopes it without touching the existing file's wording.
anchor_tail_absent_scope =  "code against THOSE" above means the entries that list endpoints or response fields; an entry whose body is marked not-in-this-conversation has none of those here — read it again rather than guessing what it said.
