# What cria answers when a READ would return more than it can hand over whole. Parsed by load_map.
#
# NO ELISION AND NO TRUNCATION, ON ANY PATH (operator ruling, 2026-08-12). A clip is a lie the model
# cannot detect, and stating the size of the clip does not make it one it can act on -- it still
# reasons over a partial view believing it has the relevant part. The only honest answer to "this is
# too big" is to refuse and say how to ask a smaller question. read_file has worked this way all
# along; the directory listing was capping with a note, and the coder's own command output was not
# bounded at all.
#
# Every route named below is one the coder can run with the tools it already has.
#
# `| head -50` WAS ON THAT LIST AND IS NOT ANY MORE. A runner prints its verdict LAST -- head is the
# banner and the dots -- so the one filter most likely to be reached for is the one guaranteed to
# hide the answer. It also replaces the program's exit status with the filter's, in the same
# sentence that tells the coder the exit status is accurate (5b). The file route is named first
# because it is the only one that keeps the whole output AND the real status.

exec = [{{BYTES}} bytes over {{LINES}} lines — too much to return, so nothing is shown. Nothing was truncated: the command ran and its output was discarded, not cut. Ask it a smaller question and run it again: send it to a file and search that (`> out.txt 2>&1` then `grep -n <what you are looking for> out.txt`), match it directly (`| grep <what you are looking for>`), or count instead of listing (`| wc -l`). Exit status is above and is accurate — but note that a `|` pipeline reports the LAST command's status, not your program's, so the file route is the one that keeps it.]

list = [{{ENTRIES}} entries — too many to list, so nothing is shown. Narrow it: list a subdirectory instead, or match what you are after (`ls {{PATH}} | grep <name>`), or count first (`ls -1A {{PATH}} | wc -l`).]
