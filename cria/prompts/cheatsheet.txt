# The tool cheat-sheet cria folds into the model's system message (one per turn, on the OUTBOUND
# request only) — the menu-derived tool hint (ports codex-local build_tool_hint). Its job is what the
# tool SCHEMAS can't carry: the cross-tool PREFERENCE rules (header, lead_write, shell = last resort)
# and, per tool, the concrete ARGUMENT SHAPE with example values (schema params are bare types). It does
# NOT re-describe a tool's BEHAVIOR — that is owned ONCE, by the tool's schema description: cria's
# synthetic tools in prompts/tool_descs.txt, harness-native tools in the harness's own description. So
# the synthetic-tool entries below are terse arg shapes only; the fuller entries are for harness tools
# cria doesn't schema-own (its sole voice) plus the cross-tool rules. ONLY tools in this turn's resolved
# menu are emitted, in this order, so the hint can never name a tool the model can't call.
# {{SHELL}} = the harness's shell tool name (e.g. shell, exec_command, bash); {{ARG}} = a read/list
# tool's real path-arg name, read from the resolved schema. Format is `key = value`, one per line;
# `\n` in a value becomes a real newline.
header = Tools available this turn, listed in the order you should PREFER them — call these exact names with these argument shapes. Reach for a purpose-built tool below before a raw shell command.
lead_write = CRITICAL — to create or change a file you MUST use {{TOOLS}}. Do NOT write files by shelling out (echo >, cat <<HEREDOC, tee, sed -i): the file tools are more reliable and cannot be truncated mid-write.
write_file = - write_file — Args: {"path": "<file>", "content": "<full file text>"}
edit_file = - edit_file — Args: {"path": "<file>", "old_string": "<exact snippet to replace>", "new_string": "<replacement>"}
read_file = - read_file — Args: {"{{ARG}}": "<file>"}, or add "start_line"/"end_line" for a 1-based inclusive range
list_dir = - list_dir — Args: {"{{ARG}}": "<dir>"}
view_image = - view_image — attach a local image so you can see it. Args: {"path": "<path/to/image.png>"}.
update_plan = - update_plan — record/refresh a multi-step task plan. Args: {"plan": [{"status": "in_progress", "step": "..."}]}.
request_permissions = - request_permissions — ask the harness to allow a command it would otherwise block (e.g. network access for an npm or apt install). Call it BEFORE that command, with a short justification.
write_stdin = - write_stdin — send input to a shell session started by {{SHELL}} (e.g. answer an interactive prompt). Per the tool's own argument schema.
web_search = - web_search — Args: {"query": "<what to look up>"}{{FETCH_HINT}}
web_search_fetch_hint =  Open a result in full with web_fetch.
web_fetch = - web_fetch — Args: {"url": "<url>"} — optional: "find" a section, "cursor" to page on, "raw" for the literal source. Sends a real browser User-Agent — a site this tool reads fine may still refuse a plain script (e.g. python-urllib's default UA); code you write must set its own headers.
shell = - {{SHELL}} — LAST RESORT, for commands with no dedicated tool above (build, test, git, package installs, mkdir/rm). Per the tool's own argument schema. Do NOT use it to read, write, or list files when a focused tool exists.
read_via_shell = - read a file with `{{SHELL}}` running `cat <path>` (there is no read_file tool this turn).
