# Descriptions the model reads for cria's synthetic tools. Format: `<tool> = <description>` (one per
# line). Schemas live in writeproxy.py (the file/web tools it advertises) and loop.py (task_complete,
# advertised on coder turns); only the model-facing description is tunable here.
write_file = Create or completely overwrite a file with its FULL content. The most reliable way to write a file — you supply the whole file, nothing to escape.
read_file = Read a file's contents (read-only). Optionally pass a 1-based inclusive line range with start_line/end_line.
list_dir = List the entries of a directory (read-only). Defaults to the current directory.
edit_file = Replace ONE exact snippet in an existing file. Copy old_string VERBATIM from the file (it must occur exactly once); set new_string to "" to delete. For a small change this is far better than rewriting the whole file. If it won't apply, fall back to write_file.
web_fetch = Fetch a web page (read-only) and return its text. A LARGE page is saved IN FULL to a ./tmp/read-only/ file and you get the path back — read it by grepping that file (e.g. grep -n "<keyword>" ./tmp/read-only/<file>), or call web_fetch again with find="<keyword>" for just that section (several at once with "<one>|<other>" — each is searched separately and any that is absent is named) (or cursor="<token>" to page through it). Do NOT re-fetch the same url to see more. To inspect the LITERAL source markup instead of readable text — the actual HTML tags, attributes, inline styles, or selectors (e.g. front-end debugging) — pass raw=true.
web_search = Search the web for pages. Each result is a title, URL, and short description; results may come back inline or be saved to a ./tmp/read-only file for you to grep. Pair with web_fetch to open a specific result in full.
task_complete = Signal that the work you were asked to do is finished. If you were given ONE step to do this turn, that means that step; if you were given the whole task, it means the whole task. Call it only when the thing you were asked for is done and you have confirmed it works — never while part of it remains. Pass `summary`: a short plain-text description of what you did. This is the clean, explicit way to end (equivalent to replying with no tool call). You may use any other tool — including writing and running tests — right up until you call it.
