# The step after "Do not repeat the same call." in a withheld tool result: sized from the measured result, never a guess at what fits.
# `lines` is for a result a line range CAN narrow ({{PIECE}} is a line count that costs about a quarter of the window); `long_line` for one a line range cannot (the longest line alone is more than half of it).
lines = Get the part you need in narrower pieces instead, about {{PIECE}} lines at a time: a line range on a read tool or `sed -n '1,{{PIECE}}p' FILE` on a file, `grep -n` for what you are looking for, or `head -n {{PIECE}}` / `tail -n {{PIECE}}` on a command's output. Then continue.
long_line = Line {{LONGEST_LINE}}, the longest, is {{LONGEST}} bytes, and a line range, `grep -n`, `sed -n` and `head -n` all return whole lines, so none of them returns less than that line. Count bytes or columns instead (`head -c 4000`, `tail -c 4000`, `cut -c 1-4000` or `grep -o -E '.{0,80}WORD.{0,80}'`, replacing WORD with the text you are after). Then continue.
range = Read it in pieces with the same tool instead (it is {{LINES}} lines; about {{PIECE}} lines at a time): {{TOOL}} {{FIRST_ARGS}} returns the first {{PIECE}} lines and {{TOOL}} {{LAST_ARGS}} the last {{PIECE}}; `grep -n` finds what you are looking for. Then continue.
command = If repeating the command is safe, run it again with narrower output (the result is {{LINES}} lines; about {{PIECE}} lines at a time): `( {{COMMAND}} ) 2>&1 | tail -n {{PIECE}}` for the last {{PIECE}} lines, `( {{COMMAND}} ) 2>&1 | head -n {{PIECE}}` for the first {{PIECE}}, or `( {{COMMAND}} ) 2>&1 | grep -n WORD` for what you are looking for (replace WORD with the text you are after). If the command only prints a file, `sed -n '1,{{PIECE}}p' FILE` reads it directly. Then continue.
