# Shown in place of the middle of a command's output when it is too large to hand over whole.
# {{LINES}} {{BYTES}} {{ELIDED}} {{KEPT}} are computed, never estimated. Parsed by load_map.
#
# WHY. cria refuses a read_file over 9,000 bytes and tells the coder to grep instead -- and let a
# command printing 302,983 tokens through untouched. Measured across the battery: 71 of 538 command
# results are larger than the limit cria enforces on a file read, and the harness had already
# silently clipped 10 of them. One gemma4 java call printed 879 lines to answer "does it crash",
# which pushed the session over the compaction trigger and destroyed the notes of the step it had
# just finished -- then it ran the identical command again six calls later.
#
# This is a bound with a ROUTE, the same shape as the read guard: the head and the tail are kept so
# an early failure and a final summary both survive, the exact loss is stated, and the next action is
# named. It is not a silent clip -- that is the thing principle 5 forbids, and it is what the harness
# was already doing.

note = [{{ELIDED}} of {{BYTES}} bytes not shown — {{LINES}} lines of output, first and last {{KEPT}} kept. To see the rest, re-run the command with a filter (`| grep <what you are looking for>`, `| head -50`, `| tail -50`), or send it to a file (`> out.txt`) and grep that. Do not re-run it unfiltered: it will not fit here either.]
