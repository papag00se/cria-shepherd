gather_repeat = [you already ran {{TOOL}} with these exact arguments this gather, and its result came back earlier in this conversation. Don't repeat it: use that result, investigate something DIFFERENT, or if you have enough, output your plan.]
research_first = [before planning, LOOK: read the real thing this work depends on — fetch the source the request names and read what it actually defines, open the files already in the workspace. A plan written without reading is a guess, and whoever builds it follows it literally. Investigate now with your tools; you will be asked for the plan once you have looked. If there is genuinely nothing to read for this request, say so and you will be asked for the plan straight away.]
missing_deliverables = [your plan does not produce everything the request asked for — nothing in it produces: {{MISSING}}. Whoever builds this works through the steps and then stops, so anything no step produces never gets made. Submit the plan again with those covered, keeping the steps you already have.]
host_unread = [your plan builds against {{HOSTS}} — nothing in this session has read those yet, so their routes, their parameters and the field names they return are being assumed, and whoever builds this plan will code those assumptions in and find out at runtime. This says nothing about whether the service is reachable or your assumptions are wrong; it means nobody has checked. Go fetch EACH of them now with your own tools, read what they actually define, and submit a plan built on what you found. The finished program must NOT fetch its own documentation when it runs: that reading is research you do now, while planning.]
submit_ungrounded = [your plan names {{URLS}} — nothing in this session has fetched those yet, so they are UNVERIFIED, and whoever builds this plan follows it verbatim. This is NOT evidence they are wrong; they may well be exactly right. Go fetch EACH of them now with your own tools and see. Name in your plan only the ones that answer; for any that do not, read the service's spec or docs and name a route they really define. Either way the finished program must NOT look the route up when it runs — that reading is research you do now, while planning.]
