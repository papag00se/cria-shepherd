# The ledger records every web_fetch this session, and a fetch that FAILED is not the same kind of
# fact as one that succeeded. Presenting them in one undifferentiated list let the anchor tell the
# coder to "code directly against the endpoints listed above" when the only entries were two 404s on
# a domain it had hallucinated — cria restating a dead URL as a REAL result it already had.
# The `failed` note used to volunteer causes: "401/403 means it exists and wants credentials, 429 and
# 5xx mean try later". Walked on ada-handles_mellum2_codex_poff_1785714194 call 0023 — the model's very
# next reasoning proposed "the API is rate-limiting" and "maybe the holder endpoint requires
# authentication", cria's own two examples read straight back, for a 404 whose actual cause was a wrong
# value in the path. A menu of causes is a menu a stuck model orders from. It now points at the one
# thing that is checkable and was true: compare the value you sent against the parameter description.
# The "you have no content from them" clause is also gone — it was false. cria HAD the 404's 89-byte
# body, `{"error":"holder_not_found","message":"Holder not found"}`, and had replaced it with a key list.
# {{HEADER}} is the caller's subject line (the coder reads one wording, the step critic another).
