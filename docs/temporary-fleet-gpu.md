# Temporary fleet GPU use

The canonical fleet remains pinned to the RTX3080 (`GPU-393d4998-707c-0ef0-a514-761015477256`). The operator explicitly authorized one `ornith1.5_9b / Java` run on the idle RTX3090 (`GPU-907a7f7a-b541-8208-2bce-e1361e3110d6`) on 2026-10-25, with restoration afterward. This is a disclosed hardware variation, not a change to weights, native context, role sampling, precision, sandbox or classifier inference. The classifiers remain CPU-only.

`suite/fleet_gpu.py` is the shared device selector. Its byte-identical installed copy is `~/.local/share/cria/fleet/tools/fleet_gpu.py`; `scripts/fleet_gpu_lease.patch` records the installed fleet launch/PID-guard integration. Without a lease the existing RTX3080 behavior is unchanged. Profiles, historical restoration proofs and model configurations retain their original device. An explicit owner-bound lease changes only the selected model's process environment and its matching actual-GPU PID check. The campaign records the exact lease and hashes both the installed helper and fleet tools; a helper that differs from the campaign source is refused.

A lease is complete, exclusively published JSON at `/run/user/<uid>/cria-fleet/gpu-lease.json`, mode 0600, bound to the supervising process's PID and start time. It exclusively names one model. Invalid permissions, malformed data, a dead/reused owner or another model refuse launch rather than silently selecting a different GPU. The volatile path disappears on reboot; it never edits the persistent RTX3080 profile.

Run `scripts/temporary_fleet_gpu.py` only under a supervised systemd unit with `KillMode=control-group` and an `ExecStopPost` invoking the same script's `--cleanup`, with exactly the same model, unit, GPU, operation and receipt directory. This second cleanup covers a killed wrapper as well as normal `finally` cleanup. The wrapper refuses any pre-existing managed model or target-GPU compute workload, so it cannot borrow the GPU by stopping someone else's model. The command inside remains the supported, planner-off sandboxed suite launcher, never bare Codex.

Cleanup stops only the leased model unit, restores byte-identical pre-cell configuration when the current bytes are the known scoped sampling configuration, and reloads the service. Newer operator edits are preserved, not overwritten. Ownership is retained until restoration and its receipt succeed: a failed restart can be retried even if the original bytes were already written. Only then is the lease removed and canonical RTX3080 selection verified. The temporary RTX3090 backend is stopped; restoration does not start a model on the RTX3080 while the operator is gaming.
