# Decision log — what retired goal, plan and investigation docs left behind

Completed plans, goal loops, replays and evidence dispositions are removed from the tree once their fixes settle (operator policy, 2026-10-13: durable outputs are repository changes and real call logs). This file keeps only the decisions, invariants and lessons that are not already owned by [principles.md](principles.md), [heuristic-assists.md](heuristic-assists.md) or the code. Raw evidence stays in the call captures under `~/.cria/calls/` and in git history (`git log --diff-filter=D -- docs/goals docs/forensics docs/tasks`).

## Architecture decisions

- **One driver, plan-off is a one-item plan (route unification, July 2026).** Plan-off runs through `Loop.drive` as a *synthetic* one-step plan; the planner is an internal on/off stage. The invariants that made this safe still hold: (1) the stall/satisfaction off-ramps live only in the single-item path, keyed on an explicit `synthetic` flag, never on `len(items) == 1` (a real planner one-step plan must not get them or lose its step text); (2) a synthetic plan frames the RAW task, no "step 1/1"; (3) a plan is persisted only under a stable session key — an unstable `task:` key is ephemeral, or the plan cache leaks across sessions.
- **Path parity ("presence is not parity").** A shared function invoked with a degraded default on one path is a silent downgrade. Capability hooks both drive paths must wire are required keyword arguments, not defaulted; every role's calls go through role resolution, never a hardwired upstream.
- **Backends, not local/cloud.** The real axis is transport: an OpenAI-compatible HTTP endpoint (llama.cpp, groq, openrouter — location is just the URL) versus a subprocess-OAuth CLI family. Roles name a backend plus sampling/reasoning; reasoning on/off is translated per backend (chat-template kwarg, `reasoning_effort`, openrouter object, or none). A raw-completion provider cannot be an agent-runner CLI (codex resolves as a precise error).
- **Termination.** The July plan ended a never-green session by handing control back to the user. That is superseded: cria never ends a session by handing back to a human (AGENTS.md, fail-safe). Surviving ideas: the no-progress sensor (same failure signature across K gates) feeds steering, and "green with zero tests executed" is *evidence for the completion judge*, never a deterministic block (it would wedge a test-free task and push a weak model to fabricate tests). A self-recursion AST detector was dropped: a self-call with an unchanged argument is not proof of infinite recursion.
- **cria owns context management; harness compaction is a dead end.** A Codex `exec` session never compacted however large the reported usage; the Codex-side overflow was ~34K tokens of unrelated MCP tool schemas (127 tools, 70% of a 48K window). Running against a stripped `CODEX_HOME` was a crutch, not a fix. The fix is the final-wire context floor (`contextfloor.fit`, applied in `Upstream._prep`), which bounds the tool schema as well as history: a 486K-token request became a 24K prompt with zero llama `exceed`. Reported usage stays truthful (the pre-floor model-visible size). An incoming harness compaction is survived structurally (a rewritten conversation root under the same session key is a continuation, not a new task). Under-reporting incidents ran with no floor in effect; see [codex-context-window.md](codex-context-window.md).
- **cria owns the coder's system slot when it orchestrates.** Harness boilerplate (7,827 tokens, 33% of one request) buried the step instruction and was the root of a redo-loop; the coder is framed with cria's own concise system prompt while the user's AGENTS.md and environment are kept. The raw proxy path (non-orchestrated) still forwards the harness prompt, deliberately.
- **A critic that only syntax-checks makes "done" hollow.** The ground-truth probe must RUN the tests on a test step; an unparseable verdict fails CLOSED, with a reasoning-off retry because a reasoning model can burn its token budget and never emit the verdict.
- **Assist modularity (October 2026).** Every assist is understandable, selectable where its contract permits, and removable; the registry is the source and `docs/assist-inventory/` is generated from it. Uniform extra event tags were an assistant-added requirement and are out of scope. No per-unit release gates, freeze/hash manifests or approval chains belong to this work.
- **Dependency surface must look where the build keeps its cache (O8).** The jar/crate/module locators first read the home defaults, then a bounded search under the harness-declared roots plus a build-printed `-Dmaven.repo.local` shown in a tool result (assistant text is never a source). Without roots nothing changes. Still unbuilt: a failure-driven listing that names the real classes in the namespace a failing check output mentions, filtered by what the disk actually holds (see [audits/o8-dependency-api-facts.md](audits/o8-dependency-api-facts.md)).

## Lessons from retired experiments

- **Two ornith1.5_9b / Java recovery treatments were rejected (October 2026).** Appending a historical check observation to the recovery notice (6 pairs at one checkpoint, 3 each at two more) did not move the coder from build/cache investigation toward source repair, and all nine complete replacement importers compiled with `javac` failed. A labelled measurement observation (3 pairs) did not stop the coder from substituting replacement details for the measured implementation, and used twice the completion tokens. Each concrete packet change was rejected; context shaping in general is not. The reasoner-directed alternative belongs to the existing stalled-work owner and was not rerun.
- **Replay harness defect: `prompts.fill` fills UPPERCASE template tokens.** An experiment template with lowercase placeholders reaches the model with literal placeholders and invalidates the comparison. Assert the exact selected evidence occurs in the rendered request before dispatching a replay; keep invalidated runs out of conclusions but do not erase them.
- **Replays are repeated comparisons, not paired trajectories**: no fixed seeds, arm order alternated. Verify proposed code by compiling it in private scratch, never by running a generated program or a model-authored shell command.
- **Private reasoning can live inside `.response.json`**, so excluding only `.reasoning.txt` sidecars does not keep it out of training or exports.
- **Recovered drafts without their native captures are not WALKs.** Two recovered September forensic drafts (gigachat31 shipping/cart/orders, ornith1.5_9b feed importer) had their ledger rows and the dependency-cache repair confirmed, but their native captures and workspaces were gone, so their causal narratives were never verified. Their proposals (first-write vetoes, lexical path rules, new retry thresholds, automatic symbol inspection) were deliberately not installed: an unread first write must not block a valid first attempt, a repeated directory name does not prove an invalid path, and a compiler's unresolved symbol does not authorize an API chosen from memory.
- **Partial capture recovery is labelled.** In October 2026 77 authentic September capture files were restored into eight native session directories (missing-only, exclusive creation, original bytes preserved, nothing invented); 20 required capture files and three workspaces remain unrecoverable, so tests that need them fail until they are rebuilt from other evidence.
- **Bonsai 2 L5 closure (September 2026).** All six L5 cells closed above 75% (85/90/95/85/95/90) through the walk → candidate → adversarial check → exact-capture replay → fix → rerun loop. Rejected candidates matter as much as accepted ones: a cart "non-execution" candidate was rejected because the capture proved the write executed after the rumination retry; a feed self-compaction candidate was rejected because the active consumer boundary was elsewhere. Generic walk dispatch stops when repeated segments converge on known classes without new causal owners; coverage is reported, never called exhaustive. A restart of `cria.service` by a queued job followed immediately by a one-shot health probe killed a battery chain — restart and probe must be separated by a readiness wait.
- **Live-test mechanics that still apply:** cria's log is named by **UTC** date; use a fresh throwaway workspace per run; verify with real `pytest`, not the critic's word; run Codex only through `suite/run.py` (see [suite/README.md](../suite/README.md)).
