# System 1 real-call continuation, November 2026

The operator directed deployment of the continued two-family System 1 candidate after reviewing its mixed evaluation. On this machine, `cria.service` uses the explicitly configured local bundle `~/.cria/models/system1/l5-continuation-001`; the repository's default `cria/system1_bundle` remains the original expanded-v2 artifact. This configuration change does not replace the artifact distributed with the repository. To restore the original locally, set `[system1].bundle_dir` in `~/.cria/cria.toml` to the absolute path of `cria/system1_bundle` and restart `cria.service` when safe.

The continuation started from the expanded-v2 native checkpoint and replayed all 836 prior training cases along with 135 unambiguous, assistant-reviewed November 6 real inputs. One CPU FP32 epoch completed 61 updates. Sessions were split before fitting, complete inputs were deduplicated, and ambiguous inputs were not hard training targets. Neither private reasoning, original model predictions, reviewer rationales nor audit outcomes were supplied to the classifier as training inputs. All labels described here are assistant-reviewed, not human gold.

## Observed tradeoffs

- On 21 non-ambiguous reserved real inputs from two sessions, original and candidate INT4 each matched 20 labels and made identical decisions. The original already correctly classified all four PLAN examples; this set cannot establish improvement on missed plans.
- On 135 exposed November training replays, original matched 113 and candidate 123: 11 prior errors changed to the reviewed label and one correct decision became a false rejection. Four corrections were related revisions in the same session. This is training replay, not independent accuracy.
- An additional outcome-blind sample of 32 earlier suite sessions was selected after the first comparison, before its own predictions and independent labels were inspected. On 29 non-ambiguous inputs the original matched 22 and the candidate 23, correcting two missed plans and introducing one. Three uncertain inputs are separate; the policy-adjusted standing is 23/32 for each, using two uncertainty corrections recorded after prediction exposure. Same-task cases may be related. The sample is not a general accuracy estimate.
- Both artifacts matched all 64 earlier synthetic controls across the two families and all 130 earlier real training replays; the latter were exposed in the original expanded-v2 fit. Neither result establishes coding usefulness.

## Export and local rollout

The saved CPU INT4 graph and external data total 239,829,460 bytes. On 364 complete inputs, the candidate's native FP32 and normalized FP32 ONNX logits met `rtol=atol=0.0002`, with maximum absolute error 0.0000692; runtime and captured input token IDs matched. Candidate native and INT4 choices differed on one exposed replay; the original differed on seven. The longest assessed full input was 3,197 tokens. Separate runtime probes checked over-budget and over-window refusal for both families without clipping; they did not establish successful full-window inference.

The candidate was packaged through `suite.system1_package`, loaded with the service's production Python environment, and checked on a real retained control for each family. On 2026-11-07 the service was restarted with the explicit bundle path and logged `system1.loaded` for `l5-continuation-001`; `/health` returned `{"status":"ok"}`. The coding model, planner settings and original bundle were not changed. Observed results are a bounded tradeoff, not a claim that this candidate is universally more accurate.

The checkpoint, full source inputs, review labels and predictions, CPU fit/export artifacts, scripts, and detailed analysis remain under the gitignored local `training/system1-v2/l5-continuation-20261106/`. They are not committed or independently backed up by this change. The next source question is whether separately reviewed, distinct-session real examples of task restatement versus a proposed repair and copied guidance versus reported prior intent reproduce this tradeoff. Any further fitting that uses these evaluation labels exposes those sets and requires different sessions for evaluation.
