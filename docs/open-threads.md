17. **Atomic snapshot: what stays open** (design in multipart-and-retention.md). (a) A read over `MULTIPART_SNAPSHOT_MAX_BYTES` (4 x the reference window in bytes) or with an unwritable `$TMPDIR` keeps the old detect-and-fail-closed paging, so a hot writer can still make such a read unrecoverable and a change-and-revert there is invisible; (b) the first page is one read through one descriptor with `fstat` before and after (an in-place writer inside that read is detected, not prevented); (c) the changed-since comparison is made when the last page runs, so a change between that page and the model reading the result is not seen; (d) an abandoned read leaves `.ctx-mpsnap-<token>` in the harness `$TMPDIR` until `python -m cria.retention prune --kind snapshot --older-than ...`; (e) a retried LAST page finds the snapshot removed and fails closed as unverified. 18. **Completion marks (owner `completionmarks`, `probegate.unsettled_writes`; mechanism in check-evidence-custody.md).** (a) Carriers are reads, listings, the gate and the write/edit programs only: a `web_fetch`, a search, a native shell command and an MCP/other-tool next action carry no query. (b) A restart loses the in-process `GuardState.gate_marks`, marks of calls older than the newest 64 (they stay in the private 0700 directory until the TMPDIR is cleared) and any write whose call never reappeared in a history. (c) A writer killed or never started stays `incomplete` for ever (a dead writer and a slow one are indistinguishable), so the gate hold repeats up to `MAX_COMPLETION_CHECKS` (4) until a later landed same-file rewrite supersedes it. (d) Real-coder evidence is n=1 per arm in two runs (the notice changed the coder's trajectory once, in the one case where nothing else exposed the missing file): the arm that needs measuring is a control where the hung file is the UNVERIFIED deliverable, n>=8 per arm, with the coder's own verification command falling in both arms.
19. **Automatic retention is off and needs an operator decision; image sessions are never closed in-process (AUD2).** See decisions below. (a) Nothing closes an `ImageSession` in production (`ImageStore.release`/`confirm_close` are reached only from `retention`), so a long-lived cria keeps one open directory fd (`imagepersist.Hold`), the session's records in memory and its directory for the life of the process and `auto_prune_after` can never reclaim them (a live holder is skipped by design); with `tools.workspace_image_tool` set, `ConfiguredImages.capture` opens a session for EVERY session key. (b) `_scan_images` re-reads and re-hashes every retained image of every unheld, unsealed session on every pass, before the age filter (linear in retained bytes per hour). (c) `workspace-reads.json` is rewritten whole on every registered read and `ImageWorkspace.resolve` walks every read per request (quadratic over a very long session). (d) A `retention prune --session` prefix of >=8 hex selects every multipart entry it matches (the dry run lists them first). Also open: a closing reply is judged only for plan-off done claims (a plan-on or scheduled review does not carry it), and a non-image deliverable that is only a statement has no reply in the judge's evidence.

## Decisions awaiting the operator

- **Automatic retained-state cleanup** (`e77b1087`): exists, OFF by default. cria has no trusted session-close signal (measured with real Codex 0.159.3: nothing is sent at exit, `/clear`, `/quit`, SIGINT/SIGTERM or compaction), so it never infers closure from idleness. To enable, set `[retention] auto_prune_after = "14d"` (minimum `1h`; optional `auto_prune_every`, default `1h`) in `~/.cria/cria.toml`; that setting IS the deletion authority. Choose an age longer than any conversation you will resume. Not enabled live. Linked: closing live image sessions by the configured age needs the pruner to reach the live store (item 19a).
