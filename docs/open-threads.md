## Decisions awaiting the operator

- **Nothing closes an image session in a running cria** (item 19a). Evidence: `ImageStore.release`/`confirm_close` are reached only from `cria.retention`; `ImageStore.session` keeps every session in `_sessions`/`_all` and each holds one open directory fd (`imagepersist.Hold`, a shared flock) plus its records in memory for the life of the process; the holder is skipped by `retention` by design, so `auto_prune_after` never reclaims a session the running process still holds. With `tools.workspace_image_tool` set, `ConfiguredImages.capture` opens a session for EVERY session key that offers the tool, image or not. On this machine `~/.cria/images` is empty and the fd limit is 524,288, so nothing is exhausted today (cost is fds, memory and disk per session key, unmeasured under load). Options: (1) leave it and document the cost (no change in authority); (2) let `AutoPruner` reach the live store and close sessions untouched for `auto_prune_after` through `ImageStore.release` (the configured age is already the deletion authority for the on-disk case; the open risk is a conversation resumed after the age, which then gets the typed unavailable path for its images); (3) open a session only when an image is actually present (not for every key when the workspace tool is merely offered), which shrinks the population without closing anything. Idleness/LRU eviction is excluded by the doctrine (no trusted close signal, measured with Codex 0.159.3). Implemented: nothing.
- **Automatic retained-state cleanup** (`e77b1087`): exists, OFF by default. cria has no trusted session-close signal (measured with real Codex 0.159.3: nothing is sent at exit, `/clear`, `/quit`, SIGINT/SIGTERM or compaction), so it never infers closure from idleness. To enable, set `[retention] auto_prune_after = "14d"` (minimum `1h`; optional `auto_prune_every`, default `1h`) in `~/.cria/cria.toml`; that setting IS the deletion authority. Choose an age longer than any conversation you will resume. Not enabled live. Linked: closing live image sessions by the configured age needs the pruner to reach the live store (item 19a).
- **Re-adjudicate "withhold a steer that contradicts the session's own response shapes"** (refused twice on the 98-run corpus; counter-evidence 2026-08-04: two ledger-disprovable steers/plan steps that arrived BEFORE the write they caused). If revisited, the fix belongs in the steer author's prompt (fence it to the parsed field names), not in a downstream deletion; re-open only with >=5 runs on current code showing the false claim still happens (decision-log).
- **Two elision roots left to the operator:** `content_reduce.INLINE_RESULT_MAX_BYTES = 9000` still bounds eleven model-facing paths and cria's own source calls the belief behind it "outlived its evidence" (measure it from the wire, as `note_harness_cuts` already asks, or keep remembering it); and `toolmenu.focus_tools` drops a harness's native search, which in a deferred-tool harness removes the model's only route to most tools.

Measured on 667 real searches: it would put a reasoner call on 475 of them (+232, about 2x), 23 of 40 sampled non-matches read as repeats by the judge (missed repeats cost wasted searches, not wrong refusals), and the judge is unstable on version bumps (2-6 of 8 new-direction on identical input).
