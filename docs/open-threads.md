## Open — completion marks: what is still not known (2026-11-01, wave 10 MARKS)

**Built since the OVER entry** (`cria/completionmarks.py`, `gatecleanup`, `probegate`, `writeproxy`, `wsview`; see the last section of [check-evidence-custody.md](check-evidence-custody.md)): (1) the mark query now rides every carrier that can ask, not only the next write/edit program. The completion gate's worker reads the marks of the session's unreplied writes BEFORE the checks start and AFTER they end and declares both in the completed transport's own metadata (`bounds.marks`, never in checker output): a witnessed `did_not_run` is a proven unlanded call (`GuardState.gate_marks` -> `denial.unlanded_call_ids(..., extra)`), a mark final before the checks leaves a verified tree, and anything else (no mark: running, killed or never started; or one that appeared only while the checks ran) is an UNSETTLED write - the gate is partial (`gate_is_partial`), the clean reading is not recorded, and completion is held with a typed notice naming the file (`prompts/gate_unsettled_writes.txt`), bounded by `MAX_COMPLETION_CHECKS` like the unknown-evidence veto. A `read_file` / `list_dir` lowered while something is outstanding carries a body-less survey-kind record whose typed `pm` report is the same read-back (`wsview.marks_ride`; composed only when something is outstanding, otherwise byte-identical). (2) The gate releases the marks cria has already learned through the authenticated reader and retires its own empty certified directory through the owned retirement (never a prefix scan, never while a writer is outstanding). (3) The sentinel declares each write's mark nonce (`cm`), so `represent_inbound` re-derives the unresolved registry from the history after a restart (`completionmarks.adopt`).

**Still open.** (a) Reads and listings only: a `web_fetch`, a search, a native shell command and a MCP/other-tool next action carry no query (no wrapper is added to native commands; a fetch's first line is not guaranteed to be a record, and the survey slot after it would be text). The write/edit programs, reads, listings and the gate are the carriers. (b) What a restart still loses: the in-process `GuardState.gate_marks` (a gate witness that no history record repeats; the next gate or write program re-reads the mark), marks of calls older than the newest 64 (release is queued for the newest only; older ones stay in the private 0700 directory until the TMPDIR is cleared), and any write whose call never appeared in a re-presented history (composed, never run, never reported). The marks of calls first learned at the LAST gate also remain (released at no later program). (c) A writer that is killed or never started stays `incomplete` for ever, so the gate hold repeats up to `MAX_COMPLETION_CHECKS` times even after the coder rewrote the file (the rewrite waits the bound for it and says `late`, which the doctrine already reads as an unestablished touch): there is no way to tell a dead writer from a slow one. A superseded-by-later-landed-write rule was written and removed: a later write that is not `late` has by construction seen the earlier writer's mark, and one that is `late` does not settle it, so it never fired. (d) Whether the witnessed state changes a real coder's trajectory: see the measurement below.

## Closed (2026-11-01, measured): a command cria composes cannot exceed 128 KiB — and the model's own write does not reach it

**The bound.** The harness runs `bash -lc "<command>"`, so every command cria composes is ONE argv string, and Linux caps a single argument at `MAX_ARG_STRLEN` = 32 pages = 128 KiB. Nothing inside the command escapes it — a heredoc, chunked printfs and base64 are all bytes in that same string. Codex reports the overrun as `Argument list too long (os error 7)` and fails the WHOLE exec. The fetch spill (`writeproxy._spill_command`) was where it was observed and it states its own bound (`SPILL_CONTENT_MAX`) and cuts with disclosure.

**The unmeasured path, now measured.** `writeproxy._write_command` — the model's own `write_file` — has ~13 KB of fixed program plus 4/3 base64, so its ceiling is ~88 KB of content. Walked on the first two `ternary-bonsai-2` L5 cells (`shipping-rates-rb` 5%, `cart-billing-go` 0%).
Across ~54 model calls the coder wrote **one file** (a Gemfile) and never touched a task file.

## Closed — when to compact is a predicate over measured room, not a configured trigger (2026-10-30)

`[context] trigger_compaction` and `windowcaps.SELFCOMPACT_TRIGGER` are gone (a config still carrying the key fails at startup naming it). A view is compacted NOW iff one more turn of MEASURED growth (the largest of the last five turns the view grew by; the largest single message before any turn) would not fit EITHER bound: the coder's (`(view + frame) × learned density + reply reserve ≤ window`, past it the floor drops turns) or the compaction calls' (`evidence × summary density + prompt frame + writer reply cap + verdict reserve + facts ≤ window`: the writer and every validator read the whole view). Unknown window: no room, so only floor pressure and a step boundary compact. `Loop._compaction_room`, `selfcompact.view_room` / `expected_growth` / `evidence_tokens`; `tests/test_compaction_room.py`.

**Why the pinned 28,884 at 49,152 was wrong, not merely arbitrary.** 49,152 − the live coder reserve 16,384 − 28,884 = 3,884: the pin is `window − reserve − frame` at density 1.0, a hand-derived version of this formula that ignores the learned density (1.13–1.2) and the real frame (system + root + tools ≈ 7.4–8.0K est. measured on the 8 sessions below, not 3.9K). ## Open — `_note_dependency_surface` withholds a coordinate for the session by the budget of the request it was first gathered in (2026-11)

A coordinate whose real surface does not fit the REMAINING byte budget the first time it is gathered is recorded in `depsurface._WITHHELD` for the session and never gathered again. "Remaining" depends on what earlier coordinates took in that same request, so a surface that would fit alone (for example once another coordinate leaves the manifest, or after a window change) stays a pointer forever, while the note truthfully says it will not appear automatically. Judged a deliberate bounded trade, not a defect: the alternative was a fresh `javap`/`go doc` subprocess on every turn (round 3), and the pointer carries the real read command. If it matters: keep the gathered surface (not just the pointer) so phase 1 can re-render it when budget frees, which costs memory per withheld coordinate and no gather.
