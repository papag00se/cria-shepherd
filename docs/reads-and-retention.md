# Reads and retained private state

## Reads

`read_file` (and the read that answers a write held because its file was never read) is carried out by cria's engine through the harness's fixed `read` primitive ([harness-primitives.md](harness-primitives.md) §5.1, §8.7; the design of record and the migration is [harness-programs.md](harness-programs.md)). The harness returns bytes and the file's identity; every decision is made in the cria process (`cria/readops.py`, `cria/ops.py`, `cria/filecache.py`), and the model reads exactly the text it has always read.

* **Pages.** The first frame reports the file's size and sha-256, so cria knows how many pages remain before it fetches any. A page is sized from the compression the last sizable frame showed (the first assumes 2.7x: 16,000 raw bytes); remaining pages go out as parallel byte-range reads, at most 8 per reply. A frame the harness cut (over its 10,000-byte result bound) is asked again at half the size. A window (`start_line`/`end_line`) is numbered `N: text` by cria (see Windows below).
* **One file state, no snapshot.** Every frame carries the sha-256 of the whole file as that call saw it. Frames that disagree, or whose assembled bytes do not hash to it, mean the file changed under the read: it is read again once, and a second change is told to the model (`⟦ctx:read-source-changed⟧`, no read credit) instead of delivering a mixture. There is no private copy of the file anywhere; equal hashes are one file state.
* **A file that cannot fit.** A whole read of a file whose chars/4 estimate exceeds the model's whole measured window is answered from its first frame (`⟦ctx:read-not-delivered⟧` with the measured size), without transporting it; a first page without a newline (possibly one enormous line, whose measured shape the note needs) and any borderline file are transported and decided at the wire exactly as before (`ReadFitOverflow`: the verified read is *withheld* in the ledger and the model told, with its shape). A file larger than cria will hold (16 MiB, `filecache.CAP_BYTES`) is never transported.
* **What the model sees, and what it earns.** The final text of a read is a field of the ledger record; the verified body (source size and sha-256, the exact bytes) is bound to the model's wire (`ProtectedRead`) until the wire accepts it (`settle`), exactly as before. A refusal (missing, directory, unreadable, inverted range) is cria's own marked text followed by the logical exit note; a non-text file, a withheld read and a read that could not be verified carry no content and no read credit.
* **Links.** A symlink below the workspace is refused by the primitive, resolved by cria, judged again by the same guards as the path the model named, and read (a link to a file outside the workspace is refused: reads used to follow it).
* **The cache.** cria keeps the bytes it read (16 MiB, least recently used); a repeated read costs the harness a stat and a hash (`read` with `LEN=0`) and no file bytes in the transcript, and is served from the cache only when the harness's fresh sha-256 and size equal the cached ones.
* **Windows.** A window is asked with `SK = start - 1` (the harness counts the newlines in the pass that hashes the file), so it is one or two frames wherever it sits, never the prefix of the file; its lines are numbered from the start line by cria.

## Retention: nothing is deleted unless the operator says so

There is no trusted session-close authority. This was measured, not assumed: real Codex (pinned 0.159.3, `exec` and the TUI) sends no request at exit, `/clear` (the next turn simply carries a new `session-id`/`thread-id`; the old one is never mentioned again), `/quit`, SIGINT/SIGTERM cancel (the connection just drops) or compaction (an ordinary `POST /v1/responses` with `request_kind: compaction`, the same `session-id`, an incremented `window_number`); Chat Completions clients can only supply `X-Cria-Session-Id`, a name with no close semantics. So retained private resources are not deleted on request end, model completion, cache eviction, compaction or idle timeout. Operator call captures and backend caches have separate retention. Deletion authority is the OPERATOR's, in one of two forms that share one selection and removal implementation (`cria/retention.py`).

**1. The explicit command** (default: nothing is deleted).

```bash
python -m cria.retention list  [--kind image|transient|all] [--tmp DIR] [--json]
python -m cria.retention prune [--kind ...] [--tmp DIR] [--older-than 14d] [--session ID] [--apply]
```

`list` shows every retained entry (size, age by last touch, state, kind). `prune` is a dry run unless `--apply`, and needs `--older-than` and/or `--session` so a bare invocation can never select everything. Snapshot directories (`.ctx-mpsnap-*`, `.cria-mpsnap-*`) and `~/.cria/multipart` are the state of the multipart read bridge, which no longer exists; earlier releases may have left some, and `retention` no longer lists or removes them (delete them by hand). `--kind transient` (same rules, same temp directory, never in `all`) sweeps the credentialed scratch directories killed lowered programs leave: `.ctx-done-*`, `.ctx-edits-*`, `.ctx-private-*` and the earlier `.cria-done-*`, `.cria-edits-*`, `.gate-private-*`. Never a prefix sweep: a directory is removable only if it is owned by this user, mode 0700, and its own `.owner` certificate names exactly that prefix, credential and inode, and it holds nothing but regular files (the gate's `aux/` may also hold plain files and directories); the inode and certificate are checked again at removal.

**2. A standing instruction.** Set `[retention] auto_prune_after = "14d"` (minimum `1h`; default unset = off; optional `auto_prune_every`, default `1h`, minimum `1m`; both `<n><s|m|h|d|w>` strings) and cria runs `prune --apply --older-than` on `image` state itself, once at start and then on that cadence, from a background daemon thread. It is the operator's configured age, not cria's inference of closure. Transient scratch in the shared temp directory is never pruned automatically. The operations ledger (`~/.cria/ops`) has no retention sweep yet.

**Safety (both forms).** Image sessions are removed through the store's own closed-seal path (seal outside the payload, payload, seal last). A live cria process holding an image session is skipped; corrupt entries are removed only when selected by `--session` (never automatically); symlinks and unrecognized names are never touched; an interrupted run is retried by running it again. `prune --older-than` does not open or validate an image session younger than the age (it could not be selected); a `--session` prefix that names more than one entry and no entry exactly is refused with the candidates listed (give the full id). A session's workspace-image read provenance is an append-only `workspace-reads.log` in its directory (an earlier release's whole `workspace-reads.json` is still read as the base), held in memory and re-read only when the file is not the size this process left. The auto-prune logs one `retention.auto_prune.removed` / `.skip` / `.failed` event per entry (a skip is announced once per process), and cannot raise into request handling (a failure is contained and logged as `retention.auto_prune.error`).

**What pruning means for a conversation.** A request in flight against pruned state gets the existing typed unavailable path, never a fabricated read: removed image sessions are not restorable. Choose an age longer than any conversation you intend to resume. These checks catch mistakes, not an adversary: any process running as the same user can forge or delete these files.
