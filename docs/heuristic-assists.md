## Nudges — directives/refusals the model sees

- **Refusal guard** — 3 of cria's own refusals in-window (the identical-call repetition route was removed) → run the repo's checks, then a grounded reasoner redirect. The trigger is armed from the history before the forwarded call returns, so admission re-measures the same window (`loop._refusals_in_window`) and withdraws a nomination whose count has since aged below 3 (run07: 3 → 2 when the oldest refusal left the window, yet the probe fired); a withdrawal restores the unused cooldown, keeps the write window and logs `loop.refusals_withdrawn`. An eligible trigger is never swallowed, and a ran call is not itself evidence of recovery. The canned redirect is only for an author that gave no answer (cut, ruminating, unreadable, vetted away, or a recovery that answered `UNSETTLED`: stuck with no concrete action) or no reasoner; an author's settled `ON_TRACK` is an answer and delivers nothing (`groundedaction.Verdict.ON_TRACK`, #4) — the checks and each refused call already reach the coder as their own results.
- **Wheel-spin guard** — same file rewritten 5× in-window → probe + steer, UNLESS the coder's own check runs since the window opened show errors being fixed: `checkmotion` reads each run through `probeparse` (identity = file + message with digits and line numbers dropped, so a shifted line or a changed constant is the same fault) and the window restarts (`loop.wheel_spin_progress`) when an earlier error is gone from a later run and none came back; the same error in every run, an error set that only grows, A→B→A, fewer than two parsed runs, or a first write the messages no longer hold all trip as before. Real Rust cell `rust-toml-cli` (four edits, each fixing the error the last `cargo test` named) tripped it; replayed against ornith1.5_9b 8/8 replies no longer trip (control 8/8 trip); as above, a settled `ON_TRACK` delivers no canned spin text. Only writes that LANDED count: a lowering-proven refusal or unapplied edit is taken back at the next turn, and the N calls of one turn count once when sent and are judged on what landed at the next acting turn (`GuardState.spin_recheck`) — phi4 A4: nine refused edits in one reply read as "rewritten 5 times". The edit-failure escalation ("failed N times — STOP editing") likewise counts earlier TURNS only; later failures to one file inside the same turn say they did not apply and refer to the first.
- **Rumination guard** — a mid-generation self-doubt spiral OR reasoning over the token budget → abort the stream and re-prompt.
- **Output-truncation guard** — a `write_file` cut off at the output-token cap → refuse the partial, steer to incremental `edit_file`.
- **No-tools (LEG0) nudge** — selected `completion-act-first` steering may re-prompt once per task or step: TASK at L4, STEP at L5 with explicit planning consent. Required activity accounting and completion checks remain independent.
- **Measured facts on an unnamed gap** — when the completion check is NOT satisfied but names no gap (typed diagnosis suppressed), `done_no_named_gap` is followed by what cria measured, as facts only (`loop._measured_gap_facts`): which files the coder READ are unchanged/changed on disk (size+mtime) since the first complete survey of the session (abstains without a complete baseline and a complete current listing), and whether the last reply held N fenced code blocks and no call (the `unexecuted_write` fence parse). No file or tool is named as a thing to do. The constant alone was the same bytes for twelve cycles in the A1 run.
- **Absence is a fact, not a label** — a negative diagnosis citing `workspace_absence`, over a subject that is a whole token of the EXACT task quote and that wsview proves absent, is canonicalised to `missing_file` whatever kind the judge chose (`loop.negative_diagnosis_canonicalised`); and when the plan-OFF done-critic is not satisfied with NO usable diagnosis, the plan-ON deliverable observer (`observe_task_missing_file`, complete+current survey only) is asked once and its typed `missing_file` answer replaces the unnamed gap. A1 call 0021 (exact quote, `missing_content` label) was suppressed for the label.
- **Exact form is measured from the file, then extracted, then compared by arithmetic** — a `satisfied` verdict is committed before the judge compares anything, and the escaped-JSON layout hides a file's byte-level shape (C13-C: 29 bytes approved for a task requiring 30, the final line break missing, 3/3 on replay, and again with counts appended to the broad prompt). `completionmeasure.written_file_facts` counts the CURRENT content of each file the session wrote or edited (only calls that returned a result and were not refused): the workspace view's body when usable and nothing that writes has run since its survey, else the newest whole write to that path — in BOTH cases only when no later edit/patch/harness Edit/writing shell could have touched the file (a native patch teaches the view nothing, so its body is the pre-edit file) — otherwise nothing is stated (a veto the disk can settle is settled by the disk, never by a stale write; command and path strings are never measured). On an approving verdict `completionapproval.exact_form` asks ONE focused extraction question (`exact_form_requirement`): does the task fix a counted file's exact byte size or whether it ends with a line break? The judge only extracts (quote, file, figure); cria checks the quote is in the task, the file is a counted one (paths normalised), and that the FIGURE is fixed by the quote itself — a byte count and an ending claim are each confirmed by one more focused question about the quote alone (does it fix an EXACT size in bytes — not a bound, not words/lines, not a value inside a file — and which number?) — then COMPARES by arithmetic. One re-ask on an unreadable answer before failing closed. A mismatch holds the approval and the coder sees only cria's measured lines (`exact_form_unmet`); an ungrounded or empty extraction cannot veto; an unreadable answer fails closed. A first design that let the judge decide `contradicted` itself blocked 4 of 62 real approvals (all false positives) and is retired. A10 (01a12bca) never reached an approval.

- **Declared JS runner reset** — after a non-zero configured `package.json` test runner result, deterministic manifest/exit/workspace facts go to a one-shot reasoner judgment; only `RESET` pins the next turn to that declared runner and the task-confirmed no-`node_modules` contract, while preserving the checker’s own output. It matches typed probe facts, not error wording, package names, or proposed actions; Ruby/JS and green Go checks are silent.
- **Search exact-repeat guard** — an identical/re-worded search this session → HTTP 400 before the network hit.
- **Domain-fetch steer** — a search naming a bare domain → "fetch `https://<domain>` directly" hint.
- **Fetch exact-repeat guard** — an identical external `web_fetch` (url + find + cursor) this session → HTTP 400; internal hosts exempt.
- **Failing-fetch guard** — 3 consecutive non-2xx external fetches → a "stop guessing URLs" nudge; localhost exempt.
- **Direct root-deletion backstop** — refuse narrowly recognized direct `rm` recursive-root / `find / … -delete` shell commands even with unrestricted directory permission; tokenize to avoid echo/grep/comments, and abstain on heredocs or unparseable shell. This does not inspect invoked programs or computed targets. The reader finds each segment's command word through the wrappers in `dirguard._KILL_WRAPPERS` / `_wrapped_command` (`sudo -u`, `env`, `timeout 5`, `nohup`, `nice`, `xargs`, `FOO=1 rm -rf /`), `bash -c`/`sh -lc`/`su -c`/`eval` bodies, `if ... then`, `find -exec` and command substitutions, and it resolves what the command TYPES: a literal path whose `.`/`..` steps lead to `/` (`realpath` on this host), `$R`/`${R}` with `R=/` assigned earlier in the same script text, and `find "$R" -delete`; a home directory through a variable (`H=~; rm -rf "$H"`) is refused at `none`/`read` in its own words (home deletion at `write` stays the operator's choice). `kill_refusal` judges each command word the same way (`echo pkill -f x`, `grep pkill f`, `man kill` are admitted; the incident forms stay refused) and, with the other machine-wide and remote harm rules, refuses at every level `kill -1`, power, session, disk, network, account/boot, remote deletes and fork bombs. What it cannot see is documented in the function (a kill behind a function or saved script, `ssh host pkill`, `docker exec c pkill`, `watch`, `parallel`, a wrapper not in the table, `kill $PIDS`, a pid stream selected by port, an environment value other than `HOME`, a symlink as the operand's final component, loop variables): measured on 213,404 distinct shell commands, 456 refused before and 410 after (46 newly admitted, 0 newly refused; [decision-log.md](decision-log.md#closed-investigations--the-facts-worth-keeping-julynovember-2026)).
- **Inference-free filesystem-mutation review** — synthetic writes and exact edits analyze complete candidate source, without a model. Shared path/resource facts and `dirguard` boundary rules produce `PROVEN` (block), `POSSIBLE`/`UNKNOWN` (log only), or `WITHIN_SCOPE` findings. Python has AST/dataflow analysis; JS/TS, Go, Rust, JVM, .NET, PHP, Ruby and Elixir have narrower lexical/API-contract adapters. Destruction-only adapters additionally cover closed-expression contracts in C, C++, Swift, Objective-C, Dart, Lua, Perl, R, Julia and PowerShell; that is not broader build/test support. A universal advisory scan also surfaces unresolved destructive-looking calls; it never blocks on spelling. Missing source and unsupported constructs remain unverified. Refused edits are bound to workstation-side bytes; drift requests a fresh read. The exact recovered `orders-api-py` source now blocks through production lowering without a judge or executing the source. Not containment or full language coverage: see [coverage, confidence and limits](cleanup-safety.md).
- **Shell filesystem boundary owns code versus input** — `dirguard` uses one lossless `shellinput` layout for rooted operands and relative write targets. Heredoc delimiter/body/terminator spans retain the original text; analysis projections preserve actual header redirects in either order. Literal stdin to a proven data consumer is not a file operand, regardless of numeric/path spelling. Unquoted substitutions, executable shell input, pipelines and later execution of a saved input are checked separately, including nested shell invocations and the consumer's cwd. Command substitutions retain exact source/body/end bounds: their executable bodies are checked recursively, while an offset-preserving opaque outer projection keeps a child's cwd out of its parent and leaves expanded write targets unknown. The shared segmenter keeps redirects such as `2>&1`, `&>` and `>|` whole rather than mistaking their punctuation for command boundaries. Opaque executable input, malformed ownership and unresolved write destinations are held rather than treated as permission. Known shell/interpreter contracts are lexical backstops, not complete program interpretation or a security sandbox; the harness remains the isolation boundary. At external permission levels `none` and `read`, a directory change is persistent shell state, not a dependency read: lexically external or unplaceable `cd`, `pushd` and `popd` targets are refused even for a dependency cache or declared root. Literal-path inspection remains available under the existing read permissions. The cwd check does not interpret invoked programs, sourced/evaluated scripts, traps, ambient shell behavior or symlink destinations; it is not containment. Line continuations share one lossless lexical projection with source-coordinate mapping, so command words, redirects and descriptor adjacency agree without rewriting the original command. Explicit unrestricted external permission is unchanged. No numeric-filename exemption remains.
- **Read-proof refusals name the unverified part** — one read-only proof supplies both the permission decision and a selected failure's reason/source span. A declared-readable path does not make a mixed command provably read-only. The refusal shows the coder's original text, not an analysis projection, and distinguishes an unproved environment assignment, unsupported reader form, redirect or syntax. It does not claim that an unsupported option necessarily writes, or that quoted syntax executes. No variable-assignment permission is added; literal-path inspection remains available. Marker prechecks may select a later obstacle before an earlier unaccepted segment; the message does not promise the earliest source position. Removing one unverified part is not a promise that every remaining part will pass.
- **Shared-install guard** — a package install whose destination is the user/system environment (`pip install`, `npm -g`, `gem`/`cargo`/`go install`, `apt`/`brew`) → refused with the in-project venv route; project-local installs (`npm install`, `composer require`, `cargo add`) pass untouched. The route names a binary only when the coder's shell is known to resolve it: the survey answers programs only once a write has carried one, so the coder's OWN successful run of a command (exit 0, a single command or an `&&` chain, no pipe/`;`/`||`; `dirguard.programs_that_ran`, taught to the view by `writeproxy.represent_inbound` through `View.note_program_ran`) counts as ground truth that its programs exist, and the first `gem install X` after a successful `gem list` names the direct route instead of "not established yet".
- **Missing-dependency note** — beside the latest real loader/compiler failure, quote the exact unresolved package and distinguish an undeclared dependency from an invalid package name. For Go, the note explicitly withholds `go get` as a remedy until authoritative package source establishes that the import path exists. For Ruby, when the surveyed tree holds a RubyGems install (a `gems/` directory with a `specifications/` sibling, e.g. `gem install --install-dir .bundle/vendor`), the note names each gem's `lib` directory (`probeparse.installed_gem_libs`, up to 8): a gem loads from `<dir>/gems/<name>-<version>/lib`, not from `<dir>` or `<dir>/gems`.
- **Dependency refusal events** — preserve session-scoped raw resolver coordinates, tool provenance, and event order across npm/pnpm/Yarn/Bun, pip/uv/Poetry, Cargo, Go, Maven/Gradle, NuGet, Composer, RubyGems/Bundler, and Hex/Mix; a later observable exact success supersedes the current refusal without deleting its history. Exact-name matching only triggers the existing whole-action reasoner judgment; it never vetoes semantically. See [dependency refusal events](refusal-events.md).

## Massages — silent output repair so the harness accepts it

- **write_file / edit_file ↔ shell round-trip** — lowered to a byte-exact base64 heredoc write; the recorded shell call re-presented as the original tool. Everything model-controlled rides base64, JSON or `repr` in the lowered program, so a hostile name or body (spaces, newline, quotes, backticks, `$(...)`, `;`, leading `-`/`--`, globs, RTL, 255 bytes, `%%NAME%%`, heredoc terminators as names) lands byte for byte under the exact name with no canary (`tests/write_edit/test_write_edit_aud7_hostile_text_programs.py`, a real bash and a PTY with the 10,000-byte cap). An `edit_file` reads and writes BYTES (every byte it does not name survives: CRLF, lone CR, a stray non-UTF-8 byte, a BOM; an LF `old_string` on a file that is CRLF throughout is taken in that file's convention); a NUL in a path or a lone surrogate in an argument is a refusal that did not run (`mutation_unwritable_text.txt`), never a traceback; a file name spelling a second placeholder of a two-placeholder sentence is shown unchanged. A composed command is one argv string and Linux caps one argument at 128 KiB (`MAX_ARG_STRLEN`; the overrun fails the whole exec with `os error 7`): `_write_command` has ~13 KB of fixed program plus 4/3 base64, a ceiling of ~88 KB of content, and no real write has come near it (6,161 captured well-formed writes, largest 21.7 KB; pinned by an 88 KB write that lands byte for byte).
- **Leaked-call recovery** — tool calls emitted as text (Hermes `<tool_call>`, XML `<function=…>`, Gemma-fable `<|tool_call>…`) → real calls; Gemma `<|channel>` thinking stripped.
- **Fenced-envelope call recovery** — in the same chain (`massage.recover_leaked_tool_calls`): a call-less turn whose first fenced block (text-tagged `plaintext`/`text`/untagged fences aside) is a single un-nested call object, name on THAT request's menu and arguments schema-admitted, not cut at the output cap → ONLY that first call is promoted; `content` keeps the prose before the fence verbatim and everything from the fence on (later calls, fabricated results, completion claims) is not forwarded, logged as `dropped_chars`/`later_envelopes` on `massage.fenced_call_recovered` (`massage.fenced_call_refused` carries the reason). **A call object is a SHAPE, not key names**: exactly two keys, one string (the tool) and one object (its arguments) — `{name, arguments}`, `{action, parameters}`, `{tool_call, arguments}`, `{action, args}` all parse, and the menu then decides whether the string names a tool (three keys — a schema echo, a `package.json` — never parse). **A code fence before the call is admitted iff the call's string argument is whitespace-normalised IDENTICAL to one of those fences** (≥80 chars; the draft-then-write reply), and refused when any preceding fence is a JSON object (a result/echo). Measured: 196 of 44,234 captured replies, all phi4 (+15 more recovered by the shape/identity extension, all phi4, 0 on ten other models); fabricated sessions, unrelated drafts and schema echoes are refused by the leader rule. Level 1; L0 untouched.
- **Pasted-file → write recovery** (loop, `Loop._recover_text_write`, the shared coder turn — L4+ because it needs the judge and the workspace view the massage chain lacks) — a call-less turn that typed a WHOLE file into chat under the file's name (phi4 cannot reliably emit a tool call whose argument holds newlines) becomes that file's `write_file`. The first fenced block ≥ `UNEXECUTED_WRITE_LINES` whose directly-preceding line names exactly one path; the path must resolve to ONE workspace file (unique over a complete listing) or be a new file the task text itself contains; not a quote of anything the coder was shown, not already the file's content; one focused reasoner question (`WHOLE_FILE` / `OTHER`, exact positive token, anything else refuses) settles whole-vs-excerpt (a 5-line `<dependency>` excerpt for pom.xml is never a file). Only that block is written, with the model's own bytes; the prose before it is kept, the tail is dropped and logged; the call is replayed through the same lowering passes as a native one. Every refusal is the `unexecuted_write` nudge, as before. Events: `massage.text_write_recovered`, `loop.text_write_judged`, `loop.text_write_refused`. **The nudge that follows a refusal claims only what is true (K4)**: a block the judge ruled `OTHER` (`PlanSession.pasted_block_other`) draws no `unexecuted_write` nudge (phi4 A4 0079→0080: an excerpt and a draft were answered with "the file's contents… send again", then a fabricated whole pom.xml); a block the model bound to exactly one path names that path (`unexecuted_write_nudge_path`); any other block (48% of the 293 captured firings) is told a block of code was sent as text and that nothing in it reached the disk — no file is claimed.
- **An empty `edit_file` old_string is refused as what it is** — `old_string: ""` names no text (it "matched" len+1 boundaries and was answered `matches 191 places — add surrounding lines`, phi4 A4 0024). `writeproxy` refuses it at the lowering as a call that did not run (`edit_empty_old_string.txt`): nothing changed, name the text to replace, or `write_file` for the whole file. cria authors no content; edit_file has no whole-file contract.
- **A write to a file never seen, and a call not run, are said** — (1) `write_file` naming an EXISTING file (the workspace view proves it) where the conversation holds no WHOLE read of it (a ranged/prefix read, a read whose result the harness compacted away, and the durable read ledger do not count — phi4 A4 0047: lines 1-8 of 29, then overwritten), no whole write of it by the coder, and no shell result of a plain `cat FILE` (`loop._prints_whole_file`; any other command that merely names the path abstains: no credit) (`loop.unread_target_fact`), is ANSWERED at the write lowering with the file itself: the harness runs a read of the path the coder named, and the result for the coder's own `write_file` call is the measured fact (`<path> already exists on disk (N bytes) and no read of it has been recorded this session…`), `This write_file call was not run… the file is unchanged`, a `⟦ctx:read-instead⟧` line, and the file's bytes exactly as read (`writeproxy._read_in_place_of_write`; re-presented as the coder's `write_file`; the answer carries the lowering's positional typed record and call-bound receipt (so every "did this write land?" owner — `_extract_writes`, contextfloor, focustrim's supersede rule and rejected-draft preservation — uses `denial`'s proven-unlanded result, and its content is never squashed) while `loop._extract_reads` uses the separately verified returned-body observation and counts it as a read, so the next write to that path proceeds — the hold lifts exactly when the file has been seen, never on a count; the once-per-path pass of B3 is gone: it let A3 overwrite the seed `Importer.java` and `pom.xml` unread). An unreadable file records no read until one returns. A harness-native `write_file` (not lowered) is untouched. The shell-read credit is for `cat` only. Decided on that structure, never on what the content looks like; a new file, a read file and an unsurveyed workspace are untouched; `edit_file` stays with the blind-edit grounding. (2) A fenced call `massage` refuses to promote (`prefix_fence`/`nested`/`off_menu`/`inadmissible`) now rides out as `bodykeys.FENCED_REFUSED`; the loop says which call did not run and the rule that stopped it (plus the same measured fact when it names an unread existing file) in the nudge after the call-less reply, and the pasted-file recovery's `unread_existing_file` refusal rides on its nudge. Facts only; no tool or content is chosen for the coder.
- **A landed edit repeats itself** (S2 echo, `writeproxy._ECHO_DEF` → `render_edit_echo`, `prompts/edit_echo_repeat.txt`) — when the replacement is longer than the old_string AND the lines directly after it (blank lines skipped) read, whitespace-collapsed, the same as one unbroken stretch of the replacement (≥ 2 lines, ≥ 2 distinct, alphanumeric), the echo states the counts and the line ranges. Facts only: no directive, no verdict on intent. It exists because a coder anchors old_string on a member's FIRST line and sends the whole member as new_string — that replaces one line and leaves the old body underneath (phi4/Java A8, A10, A11). Measured on the 286 replayed-and-verified landed edits in the capture corpus (123 with a longer replacement): 8 fire, every one a real duplicate; the fuzzy variant (line similarity ≥ 0.7) fired 13 and two were legitimate neighbours (an import list, a sibling test), so it was refused. NOT covered: a leftover whose lines were *altered* (A11 `knownSkus`/`worker`, a rewritten body over the old one) — exact repetition is the only measure with no false positives here; the judged extension (one focused question, after a ≥3-line replacement of a 1-line old_string) is the open follow-up. The edit executor also serialises concurrent edits and never leaves a half-written file: it resolves the path (`realpath`), takes an exclusive `flock` on the target's directory (nothing is created in the tree; `write_file` runs the SAME landing — `ownedfiles._lock_directory` / `_write_through` and `writeproxy._UNLANDED_PY` — so it too writes through a symlink, rewrites a multi-link file in place, and reports an unwritable directory as a plain result), and swaps the new bytes in with a temp file beside the target. A symlink is therefore written THROUGH (the link survives); a file with more than one hard link is written in place under the lock (a swap would split the links). The swap keeps the mode and tries to keep owner/group (`chown`, best effort); ACLs and extended attributes are not carried, and a swapped file gets a new inode. An unwritable directory is reported as a plain "could not be written" result, not a traceback. A batch of edits to one file also applies in the coder's CALL order: each queued edit carries its predecessors' indexes and waits (outside the lock, at most `EDIT_SEQ_WAIT_SECONDS` = 5 s — under the ~10 s a harness lets an unbudgeted command run) for their done-marks under `$TMPDIR/.ctx-edits-<per-translation token>`, removed by the group's last edit; a predecessor that never arrives is not waited for further and the result says the edit ran early. The repeat sentence says "blank lines aside" because blank lines are skipped when matching.
- **Rung-gated lowering options are registered assists** (`loweringoptions`; `harness-plumbing-packing` L4, `edit-result-echo` L5) — the zlib-packed edit-failure report and survey ride, and the echo window a landed edit reports, used to be `done_refusals` / `assists_enabled` flags handed to `translate_outbound` by `server`, invisible to the registry, `LEVELS.md` and `[assists] disabled`. `server._translate_out` now asks `loweringoptions.resolve(<bound selection>)`; below its rung or opted out the lowered command is byte-for-byte the one below (proved through the real server at L0-L5 in `test_server_config_levelreg_lowering_options.py`). The server's focus-trim gate likewise reads the registered `coder-focus` bindings (L3) instead of `context_fixes`. The context floor (F68) is the one L3 gate that is deliberately NOT registered (required foundation; see the operator decisions in `open-threads.md`).
- **A whole-file write that would gut a file the coder read: a FRAGMENT is judged and held; a REMOVAL lands with facts** (`Loop.shrinking_write_check` → `shrinkprotection.check_write`, the write lowering) — H2. Both are measured by `loop.shrink_measure` over a file cria holds the text of (a read or the coder's own write; unknown = silence) with ≥ 8 non-blank lines.
  - **FRAGMENT** — candidate ≤ half the file's non-blank lines AND repeats < half its distinct lines (phi4 A4: a 190-char `<dependencies>` excerpt as `write_file pom.xml` over the 28-line POM; A3: a stub over `Importer.java`; 16 of 1,156 corpus writes). WHAT IT IS goes to the pasted-file recovery's closed question (`WHOLE_FILE` / `OTHER`, `loop.whole_file_ruling`; prompts `write_call_judge*.txt`). Only a clear `WHOLE_FILE` (remembered per path+content hash) lets it run; anything else holds it: the call is not run (`denial` mark via `_refusal_command`), the result states the measured sizes/lines, how many lines would be removed and the first, and the least-indented removed block openers; the rejected payload rides after it; `edit_file` is named only when the menu has it. A hold is not remembered (an identical repeat is asked again; at temperature 0 a false `OTHER` holds identical content indefinitely; the coder's outs are `edit_file`, a shell command, or content that keeps more of the file). Bound to the bytes measured: the lowered command refuses only while the file on disk still equals them. Needs no survey baseline — the question is about the content, whoever made the file. Counts are true units (`repeats K of the file's D distinct non-blank lines`; R = multiset difference, a lower bound).
  - **REMOVAL** (cycle 12, phi4 A9: a 69-line rewrite of the 114-non-blank-line `Importer.java` lost `summarize`/`Summary`/`totals`/`main`; it slipped under the fragment test because 69 > 57) — the write removes ≥ half the file's non-blank lines but the candidate is longer than half. It is **never held and never asked**: the candidate IS a whole file, so the honest answer to the closed question is `WHOLE_FILE`, and a line threshold must not make that semantic call (principle 8). The write lands and its own result gets the measured facts appended (`write_shrink_facts.txt` `removed_landed` + `openers`): `removed at least R of the file's N non-blank lines` and the up-to-12 least-indented removed lines that open a block (next line indented deeper), in file order — indentation, not vocabulary, so a definition/class/loop header in any language and never the imports. Facts only, never a directive; printed (one `⟦ctx:removal⟧` line after `⟦ctx:wrote⟧`, re-rendered by `represent_inbound` after the `Wrote <path>` confirmation, which otherwise replaces the whole raw result) only if the write landed and the file on disk still equals the bytes measured. Only for a file in `PlanSession.first_survey_files` (listed by the FIRST survey to land — folded or incomplete included, a listed file is proven present — minus files a landed coder `write_file` created before it rode back): principle 2 protects progress the coder did not make, and a deliverable the coder created (REVIEW.md) is rewritten whole freely. No first survey = silence. Corpus: 102 of 1,182 big-file writes (8.6%) remove ≥ half the lines; 49 (4.1%) once coder-created files are exempt (approximated by "first corpus appearance was a coder write"; `~/.cria/validation/phi4-java-focused-loop/h2_removal_rate.py`).
  - **Measured live behaviour (phi4, 2026-10-11, temperature 0, `h2-fragment-write.md`): the judge answered `OTHER` on 22 of 22 runs of 11 legitimate shrinking rewrites and held all 14 runs of the fragments** — it does not discriminate honest rewrites from fragments, so for this model a FRAGMENT-class rewrite is effectively held until `edit_file`, more-of-the-file content, or the shell. That was accepted for the 1.4% fragment class and is exactly why the 4.1% removal class is facts, not a hold. No reasoner, assists off (L<5) or an unknown file: untouched. Events: `loop.write_shrink_judged`, `writeproxy.write_shrink_held`, `loop.write_removal_facts`, `writeproxy.write_removal_facts`.

## Context shaping — what the model sees and how much

The floor reductions below belong to one **required wire-fit foundation**, F68, not independent removable steering assists. The complete `contextfloor.fit` strategy shares budget, protection, schema capability, pairing and loss-disclosure obligations; its helpers run under window pressure only. The final `Upstream._prep` retains sole fitting authority and existing activation: L0–L2 and unknown-window behavior are unchanged. No disabled/per-helper fit mode exists, and remaining `over_budget` is not acceptance. This explicit [source contract](shephard.md#required-final-wire-fitting-contract) preserves the existing potentially lossy ordering and labels without declaring efficacy or broadening optional-assist migration coverage.

- **Delivered guidance remains historical context** — both coder drivers retain distinct notes only after successful transport of their exact surviving final-wire text. Later requests receive those notes as explicitly historical observations before ordinary reducers, not renewed orders or assertions of unfinished work. Typed producer provenance keeps the history out of the protected live-input span and is stripped at the wire. No turn expiry, read/write compliance rule, planner enablement or cross-task cache is introduced. See [guidance continuity](guidance-continuity.md).
- **Historical checker freshness** — the session remembers later issued invocations of a carried check through the shared shell input/argv owner, including redirects and output filters. Quotes, saved heredoc data and unresolved array/function groups do not become new check receipts; numeric argv is removed as a descriptor only when unquoted adjacency is proven. The handoff note reports issuance, not proof that execution completed or passed, and only actual returned check results supersede older observations. Filter/background/pipeline status is not attributed to the check. Checker output and the older gate verdict are unchanged; compaction does not promise that a result remains visible.
- **Own concise coder prompt** — cria's `coder_system.txt` leads the system slot; the harness's own bloated agent prompt no longer REPLACES it silently. Caller instructions ride behind it: Responses `instructions`/developer items (`responses.to_chat_body`) and, identically, a Chat caller's `system`/`developer` messages (`server.carry_chat_system`, at the Chat edge: folded in order into one marked leading system message, the first `system` text as the reducible persona, `developer` text as configured authority). cria's own safety/tool rules lead and are never displaced; a Chat caller's text is subject to the same size handling (the floor swaps the persona for its labelled `⟦ctx:reduced⟧` stand-in before it folds any evidence, on the relay path as well as the coder path). Before this a Chat system message — a 100-token persona or a 60,000-token rulebook alike — was removed by `_proxy_body` and `assemble_base` with no word to the model, while the same text as Responses `instructions` reached it (wave 9, agent L). A body with no system/developer message ships byte-identical.
- **Tool-menu focus** — curate to the coding-essential tools; synthesize lean `read_file`/`list_dir`/`write_file`/`edit_file`/`web_fetch`/`web_search`.
- **Tool cheat-sheet** — plain-language per-tool usage generated from the live menu, carried into cria's system message.
- **Window auto-detect + derived budget** — read real `n_ctx` from `/props`; budget = window − output reserve.
- **Real-token calibration** — a rise-fast/fall-slow EWMA learns the model's chars→token ratio (≈1.8× → 3.5×). With a discovered local template, the final rendered prompt is also tokenized before sending; measured overflow refits the original input through the single floor before capture/POST, while an unchanged irreducible overflow is refused. Unknown measurement stays unknown; required measurements and selected capacity recovery remain distinct from floor activation, which still excludes L0–L2.
- **File reads retain their full requested content** — whole, ranged, spilled-document and read-instead results have no per-read context allowance or fixed byte cap. Typed receipts preserve the returned bytes and their provenance; missing and unreadable files remain distinct refusals. The existing final-wire context floor remains the sole fitting owner, and an external harness may independently limit output.
- **Large reads are paged by the harness, atomically, and survive a chatty shell** — a file too large for one tool result is read as successive lowered shell calls the HARNESS runs (cria never opens the path, principle 23c). The first page copies its bytes into a private snapshot, so a writer between pages cannot tear the read; a source that changed by the last page is delivered as the first page's exact bytes labelled `⟦ctx:read-source-changed⟧` without read credit; and the page record (the line that starts with the read's private token) is found among whatever else the harness shell printed: the noise is measured, the next page limit is `max(10,000 - noise, the largest record that survived a cut)`, and a cut result whose record did not survive is asked for again at 2,000/1,000/500 bytes (8 re-fetches per read at most, then the old labelled `cut`). Real bash on a PTY with 0-12 KB of noise before and after reads a 45 KB file byte for byte; 7 KB of noise both before AND after leaves no room for any record and ends labelled unverified, never wrong. The single-call typed programs (ranged read, write, edit: `resultpacket.find_record`, record 1 = the first occurrence of the call's own receipt record, never past the harness's cut marker, or past it only with its declared survey record following) and the completion gate's page transport (the reader's wire budget follows the measured noise; a cut page is re-asked at 1,500/750/375 bytes) follow the same rule, and a re-asked page whose snapshot the last extent retired reads the path and is accepted only on identical digests and identity. Design, retention and limits: [multipart-and-retention.md](multipart-and-retention.md).
- **content_reduce** — MIME-aware lossless-first reduction of an oversized tool output (HTML→text, JSON minify) before it blows the window.
- **Self-compaction** — token-triggered: roll the old transcript middle into a retrospective `⟦ctx:rollup⟧`, keeping the tail verbatim and giving the writer the pinned original task. Two independent fail-closed judgments require exact `RETROSPECTIVE` and `PRESERVES` verdicts (no forward plan, full task scope); fidelity to the evidence is settled by lookup, not by a verdict — the figure lens (`briefinggrounding`, below) and the typed lenses below (files, changes, sizes, build state). Rejection retains verbatim history and suppresses a retry until a new token band accumulates. Rare rollup refolds pass through the same gate. Anchor identity is the message's own text: a `⟦ctx:facts⟧` note cria appended to a tool result (the producer-stamped payload boundary) rides on verbatim as its own anchor while the tool's result is summarized with its call; an unverifiable boundary keeps the whole message verbatim (run07 0075: the writer and validators read `edit_file(pom.xml)` with no result). An anchored tool result (a web_fetch payload carrying the spec routes/shape) anchors its whole exchange — the issuing assistant turn and all of its results stay verbatim together, out of the summarizer, and identical exchanges deduplicate whole — so neither the writer nor the coder sees a call without its result; the verbatim tail begins at a whole exchange too (`_whole_exchange_start`: a token cut that lands on a tool result moves back to the assistant turn that issued it, so the wire never has to re-role an orphan result as a bare user message — 60 of 315 real self-compactions rebuilt from ornith1.5_9b / Java captures shipped one, 0 after) (20261008T202854 0038; 20260813T015529 0009-coder-s2, the spec re-roled as a user turn). The coder sees each accepted increment as its own labelled, ordered entry in the rollup (`[increment N of M, written after increment N-1]`; a refold is one entry condensing K earlier increments), with the statement that later increments supersede earlier ones and real tool results or the files on disk supersede both (run07 0070 carried a false "5 fields" increment beside its later correction, unordered). A rejected increment keeps the standing summarized view rather than sending raw history.
- **Reducible internal evidence** — compactor, briefing-validator, and steer-author transcripts ride as independently reducible evidence turns between a small introduction and the final active question. With no pressure their bytes are unchanged; under pressure the single context floor can fold/drop whole evidence blocks with its existing labelled stand-in instead of knowingly sending an irreducible oversized two-message body. The inspecting author's task/current-facts/question packet uses the existing exact wire pin, so a later forced-answer closer cannot make it droppable. This restores answer capacity and retention; it does not establish better reasoner judgment.
- **One briefing per identical harness-compaction request** (`handoffmemo`, wired in `server._produce_completion_once`) — the harness retries a failed request up to three times and each retry re-ran the briefing writer and every validator lens for one history (and could accept on one attempt and refuse on the next). The reply produced for a request (session + digest of the whole inbound body) is kept with a digest of the evidence read besides the body (gate flag/age/checks, original task, the workspace listing the writer is shown); a retry with both equal gets the stored reply with no model call (`handoff.memo_reused`), a changed history, changed evidence or another session is produced afresh, and a concurrent retry waits for the first instead of starting a second writer. A refusal with no decided answer (judge unavailable, an empty or unjudged lens) and a truncated reply are not kept. Process memory only, bounded (4 per session, 32 sessions): a restart loses it and the next retry is simply produced again.
- **Chunked summary evidence** (`handoffdistill`, ported from codex-local's compaction service) — when a summary writer's evidence (the loop's self-compaction band or rollup refold, or a harness compaction request) will not fit one request in the floor's own currency (estimate × learned *summary* density, plus the writer's reply room), the older transcript blocks are cut into pieces that each fit with their own reply room (4,096 tokens at the 49,152-token window, a share of the window elsewhere — `windowcaps`), one call per piece extracts facts as JSON, and consecutive extracted pieces are merged in code (union in order, newest wording kept, latest goal/plan) into one floor-protected `⟦ctx:extracted⟧` block labelled as a model-made condensation. An extraction counts only if it matches the key/type contract and carries at least one fact; otherwise that piece stays verbatim in its original position. Recent turns and the appended facts (files on disk, last checks, pinned task) stay verbatim; the validators still read the full transcript; the empty/cut-off briefing retry reframes through the same distiller; at most 24 pieces per summary. Abstains when the window is unknown or guessed. Run 1792480002 call 0051 (a whole-middle first self-compaction, cut off after 959 reply tokens) is the incident.
- **Summary requests are sized with their own density and keep their reply room** — summary work (`cria_density_kind = summary`, or a self-compaction/compaction phase) learns its own tokens-per-estimate ratio instead of borrowing the coder's (`upstream._density_key`); the measured-prompt check requires the real prompt plus the request's reserve to fit, not the prompt alone; and when the view rolling memory would send without a new summary (current rollup, anchors, unfolded band and tail; the raw history only while no rollup exists, composed by `selfcompact._view`) would make the floor drop turns, it summarizes through its rejection throttle first (`RollingInput.floor_pressure(view)`). Raw history, which only grows, no longer counts: run07 0059–0075 bought five writers plus validators on 1–4-message middles with coder views at 14.6k–18.5k of 49,152.
- **Every bound that stands in for "how much fits" is a share of the window of the model that answers** (`windowcaps`, one owner) — the judge/classifier reply cap (`JUDGE_MAX_TOKENS`), the summary/rollup/critic/plan reply caps, the chunked extraction's reply room, the floor's default reply reserve, the self-compaction working-set sizes (verbatim tail, recompact band, refold), the dependency-note budgets (one surface inline: 6,000 B, floor 4,800 so a decimal-sized surface stays whole; the sum of notes appended to one request: 24,000 B, floor 8,000, ceiling 96,000) and the composed-evidence block size are each `reference × window ÷ 49,152`, between a floor and a ceiling, and EQUAL TO THE OLD CONSTANT at the 49,152-token window (`tests/compaction_handoff/test_compaction_handoff_room.py`, one row per cap). A `Cap` is an `int` carrying its name, so anything that does not resolve it still sees today's number; a cap placed in a request body (`max_tokens`, `cria_output_reserve`) is resolved in `Upstream._prep_wire` against that Upstream's own measured window, so a classifier/reasoner role on another server is sized by ITS window; the self-compaction sizes are resolved in `Loop._self_compact` against the CODER's window (it is the coder's view being compacted) and the dependency-note budgets in `returnedpolicies._note_budgets` against the coder's window (`represent_inbound(window=)`, from `windowcaps.known_window`; one definition, writeproxy's duplicate is gone). An unknown or only-guessed window is the reference value, never a small one; a role's explicit `max_tokens` / `output_reserve` is the operator's and is never rescaled by the table, but what the floor HOLDS of a reserve is bounded by `contextfloor.clamp_reserve` (never more than half the window, never more than leaves the live input its room), the ONE rule the floor, `Upstream` and `Loop._coder_sizing` (hence the compaction predicate) share: a 16,384 reserve is the whole of a 16K window only on paper (a real 16,384-window run held 8,192 with 0 turns dropped for the first five coder requests where the unclamped run slid from 12,469 to 1,453 est. tokens of view room). Why: a 16,384-token reply cap is a third of a 49K window and the WHOLE window of a 16K model (a compaction lens reserved its whole cap as reply room — `COMPACTION_VERDICT_RESERVE`, commit 40747fda), and 24 KB of dependency notes is 47% of a 16K window's REAL tokens (7,784 of 16,384 on four real cargo crates, measured on the real 16K server) against 17% with the window-sized budget; replaying a captured Maven session (opencsv + commons-lang3, 12,166 B of notes = 2,969 real tokens) through the production note path at 16K, the old budgets left 7 of 8 coder requests refused by the floor as `InputOverflow` and the window-sized 6,179 B (one whole surface plus a labelled pointer to the other) let 8 of 8 through. NOT scaled, on purpose: harness/OS transport limits (the survey and echo sizes, `INLINE_RESULT_MAX_BYTES`, stdout caps), safety/time/resource bounds, one-word reply reserves (`COMPACTION_VERDICT_RESERVE`, `filepresence.MAX_TOKENS`) and the measured prompt frame (`FRAME_TOKENS`) — each is written down with its reason in the `FIXED_SIZES` allowlist of `tests/structure/test_structure_lints.py`, which fails on a NEW size-like constant until it is a `windowcaps.Cap` or carries a reason. The dead `EVIDENCE_SUMMARY_TRIGGER_CHARS` / `SUMMARY_TRIGGER_CHARS` (48,000 characters; the model-made evidence summary they gated was retired in a464533a) are deleted rather than scaled.
- **WHEN to compact is a predicate over measured room, not a number anyone sets** (`selfcompact.view_room` / `expected_growth` / `evidence_tokens`, computed by `Loop._compaction_room`). There is no trigger and no `[context] trigger_compaction` (a config still carrying it fails at startup naming the key; the old 16,384-token window-scaled default is gone with it). A view is compacted NOW iff one more turn of MEASURED growth — the largest of the last five turns the view actually grew by, or the largest single message when no turn exists yet — would no longer fit EITHER bound: the coder's (`(view + frame) × learned density + reply reserve ≤ window`: past it the floor drops turns) or the compaction calls' (`evidence × density + frame + the writer's reply cap + the one-word verdict reserve + the authoritative facts ≤ window`: the writer and every validator read the WHOLE view, and nothing shrinks a validator's evidence). Each bound uses ITS model's measured window; unknown/guessed window = no room to compute, so only floor pressure (which also needs a window) and a step boundary compact. One density feeds both the room and the chunked-distillation budget (the measured summary density, else the coder's) so they cannot disagree about whether the view fits whole. After a summary stands the engine stays in compaction mode (the old cadence: recompact band, rejection memory, floor-pressure bypass). The coder bound uses the CLAMPED reserve (`contextfloor.clamp_reserve`, above). **Two small-window guards** (COMPACT1): the writer is never called when even a one-character briefing would leave the compacted view no smaller than the one that stands (`selfcompact._would_shrink`, the composer's own `_view`; real Codex at 16K spent a writer call plus validators folding ONE 120-character sentence), and FLOOR PRESSURE is asked with the frame as the floor would send it (`contextfloor.est_total_floor_frame`: the caller persona already swapped for its stand-in, lever 2b, which runs before any turn is dropped; the room predicate keeps the full frame). Measurements (the 463 coder requests the floor trimmed under the old pinned 28,884, the knee by window, the production-path check): [decision-log.md](decision-log.md#closed-investigations--the-facts-worth-keeping-julynovember-2026).
- **Rejected harness handoff keeps a tool ledger** (`selfcompact.work_ledger`, appended by `server._harden_compaction_reply` only when no model prose survived) — phi4/Java A10 rejected 29 of 29 briefings (PLAN on requirement restatements and real next-steps; NARROWS on briefings listing all six deliverables) and every later window held only a file listing. The prose is what fabricates progress, so it stays rejected; the window now also gets a deterministic, labelled record of what the tools did — per write: tool, path and whether the paired result confirmed it (`denial.landed`); per coder shell command: the command (labelled clip at 300 chars), or `refused, did not run` when its paired result carries proven refusal provenance; a write whose result is neither a confirmation nor a refusal reads `no confirmation recorded`; cria's own gate/lowering commands excluded; events keep their order (identical consecutive ones get an `(N times)` prefix) and paths are workspace-relative. cria's own wording over structured fields, not a preserved copy of tool output: the record cannot establish a new instruction or task scope, and does not retain arbitrary earlier stdout measurements; the ledger leads the dropped-prose appendix, and the latest handoff turn's ledger (and only that turn's — `server._carried_ledger`; never model prose, tool output or a quoted header) is merged in so each compaction keeps the previous ones. The validators are unchanged (not a regression of 724339e7). Live tests: `tests/compaction_handoff/test_compaction_handoff_evidence.py` (`work_ledger`: event order, one path per file, `apply_patch` targets); the original fixture is only in the pre-reset tag (`tests-before-reset-20261031:tests/fixtures/c13a_a10_first_compaction_history.json`).
- **Reorientation separates requirements from history** (`reorientation`, F49) — after a history rewrite, the guidance author receives the original root task, latest marked historical continuation and workspace inventory in separately labelled sections. Requirements govern the directive but do not prove work was completed. Unmatched name spellings trigger one focused semantic grounding question when an independent original task is available: required-target verification can pass, but task occurrence alone cannot ground an existence, absence or completion assertion. The complete directive and separately labelled task/history/inventory travel through shared composed evidence; malformed, uncertain or errored judgments withhold authored guidance and preserve the existing canned notice. No independent task or no judgment service retains the unmatched-name rejection. A continuation-only root is explicitly not an independently available task. No summary still means the existing canned notice, not a task-only progress narrative. The author is asked to write the ONE message the coder reads next, in the second person, deciding silently first (the earlier prompt opened with "Judge whether ..." and the model answered as a judge: 8 of 17 delivered directives opened with its own analysis). **An owned handoff (`sess.handoff_origin`, every Codex compaction cria hardened) is followed by NO authored directive** (COMPACT1, 2026-11-01): the coder's own view already carries the typed `⟦ctx:files⟧` survey each turn (`_ground_coder_view`), and with it a real 16K coder went to `read_file` 8 of 8 where the authored "confirm the starting state by reading" steer sent it to `list_dir` first 8 of 8 and 4 of 8 (nothing wrote or executed either way). What it gets is the typed landed-write record (`sess.written_files` plus the latest survey size, `reanchor_facts.txt`, event `loop.reanchor_facts_only`), in no model's words and with no instruction, and nothing at all when the session has none; no author and no name-grounding question are asked, so a task that forbids inspection is never contradicted. The author, the grounding question and the canned notice remain for UNOWNED continuations only (the paragraph below describes that path). A redirect is followed only to http(s): `httpread.install_http_only_redirects()` installs one process-wide opener at startup (`__main__`; `urllib.request.urlopen` stays the seam every caller and test uses, and the 302 to `ftp://` is returned as the answer; `receivecapture` admits this one installed opener and still refuses foreign ones). The coder's `web_search` is made IN-PROCESS while its call is lowered (`brave.search`, through `ratelimit.open_response`), exactly as a fetch is: a Brave 429 (the free plan is one request a second) is waited out and retried once after the stated wait, a longer one is not sent, and a refusal reaches the model as `search_refused` naming the wait the shared reader stated, with the denial mark and a non-zero exit; the lowered command only parses the compact answer (`printf` of title/url/description/error), so the key no longer rides in the harness's command. The shared reader also reads the `claude` CLI's prose "resets 5pm (America/Los_Angeles)" / "resets Oct 9 at 12pm" against the injected clock in the zone it names (this machine's when none; a zone it cannot read states no wait).
- **Preamble provenance** — system/developer roles establish context origin; user markup does not. Unproven user packets remain verbatim rather than being rewritten as an inferred harness preamble. Workspace-instruction authority is checked by its existing independent source reader, not by matching user prose to a file.
- **The model never sees the product name in anything cria composes or replays** (`privatenames`, called from `modelview.wire_messages`, so `Upstream._prep` and the usage report, and from the inbound path) — the private names are neutral (`___CTX_*`, `__CTX_*_PY__`, `__ctx_*`, `.ctx-mpsnap-`/`-done-`/`-edits-`/`-gate-`/`-helper-`/`-private-`, `CTX_RM`; retention sweeps both `.ctx-mpsnap-` and the earlier `.cria-mpsnap-`). An earlier release's names inside cria-composed commands and in the results of exactly those calls are renamed; an unreceipted declared lowering is re-presented as the tool called (the current release honours an unreceipted header only for the alias `read_file`: a coder command carrying a write/edit/list header is not re-presented as a call it never made), the survey riding on it is stripped and a survey cria composed alone is dropped; a file or tool output that quotes an old name is never rewritten. Measured: 3,454 real wire bodies after 2026-10-15 scanned in full (messages, tool calls, tool schemas, body keys) and nothing cria composed named the product; every hit was the benchmark suite's environment (its Maven repo under `~/.cria/suite-installs/` read from `JAVA_TOOL_OPTIONS`: the model called it "the CRIA one"), while 60 real bodies of 2026-10-22/23 replayed through a fresh server DID leak private lowered commands before the fix. Tests: `tests/context_wire_b/test_context_wire_b_invis_replayed_private_names.py`, `tests/structure/test_structure_prompts.py` (composed commands scanned), `tests/server_config/test_server_config_invis_fixture_session.py`. Open (open-threads): the suite's install directory shows the name to every model it drives; marks and edit-sequence directories an earlier release left are not swept.
- **Responses text is token-progressive only where nothing can precede or reorder it** (`bd850be5`; indicators silent, level below done-refusals, a proxied non-compaction non-image turn; `_chat_progressive`) — whole completion still runs the buffered post-processing and a final text that no longer starts with what was shown ends in a retryable `response.failed`; first text delta 30-36 s -> 4-9 s on ornith1.5_9b (n=2 each: a latency claim, not a rate). Elsewhere the text is buffered because a guard can still withhold or replace it: a loop turn with no tool call goes to `_gate_single_done` (the text is forwarded in a LATER response if the repository checks and the satisfaction judgement pass) and a reply WITH a call can still be replaced whole by the generation guards and re-asks; proxy turns with decorations compose `[reasoning transcript][banner][connect line][assist notes] text [stats footer]`, and the banner's `N tok/s` and a truncation note are known only at the end yet sit BEFORE the text (an operator decision about the display: open-threads). Audited and fixed (AUDSTREAM): a call the model wrote as text with no leak marker (JSON envelope, `name({...})`, fenced `{name, arguments}`) that whole-text recovery then promoted ended `response.failed` where the buffered path returns the call (a turn with tool calls now closes the item with the final text and continues); an item that cannot be built (a custom tool call with non-string input) left no terminal event; a typed terminal upstream error before any text is asked again through the buffered call; only a failed write to the harness is `client_gone` (a TCP reset from the MODEL ends with `response.failed`, never a bare EOF; tests in `tests/server_config/test_server_config_img_progressive_responses.py`). Open: with a recovered call the harness screen still shows the raw JSON text for a moment and history holds an empty message item beside the call (avoiding both would mean holding text back from any `{`); a model-stream error frame after shown text re-asks buffered and a new generation that does not start with the shown text ends `response.failed`; the live config has indicators on, so this path is never taken live.

## Probes — ground truth by doing

- **Language-aware syntax floor** — `py_compile`/`node --check`/`php -l`/`ruby -c` + a TOML/strict-JSON config floor over disk files → exact `file:line`.
- **Zero-config test floor follows the manifest** — with no declared test command the floor composes one; the Ruby floor runs `bundle exec ruby -Ilib -Itest -e ...` when a Gemfile exists, does not fire when the Gemfile declares rspec (`bundle exec rspec` is supplied and the floor would run no spec and call that green), and stands down when a Rakefile/`.rspec` exists; without a Gemfile it is bare (`probediscovery.build_ruby`, `test_floor_candidates`).
- **Repo probe discovery** — inventory 9 ecosystems (JS/TS, Python, Rust, Go, JVM, .NET, PHP, Ruby, Elixir) → ranked SAFE diagnostic commands. Every workspace-survey tree record, including folded-directory drain records, shares one byte bound; exhaustion closes an accepted `complete=0` survey rather than producing a count-mismatched partial inventory. A toolchain's BUILD OUTPUT is named, not walked (`wsview.BUILD_ARTIFACT_DIRS`: per ecosystem, a directory name plus a manifest of that ecosystem beside it, the same manifests `probediscovery.detect_ecosystems` reads; `target` with `Cargo.toml`/`pom.xml`, `build`/`.gradle` with `build.gradle(.kts)`, `_build` with `mix.exs`): the survey writes a `B` record (named, interior unknown, `View.build_output` says which manifest proved it) and stays complete, so the first `cargo build` no longer spends the whole tree byte budget in `target/` (86-107 records on a six-file crate, every Rust survey "NOT complete", absence settling off for every judge). The inventory is `bounded` only by a fold the renderer does NOT omit by name; the lint floor skips such a directory on that proof (`target (Cargo.toml beside it)`); an ambiguous name without its manifest (`build` beside a `pom.xml`) is still walked. Dependency installs (`node_modules`, `vendor/bundle`) are not in the table. The `outside` and `progs` survey sections carry the model-named path/program (and the resolved name) as base64, like the blob section, so a name with a line break cannot forge a record; a name no file system can spell (a lone surrogate) gets no record (unknown) instead of ending the survey.
- **Package-script vetting** — read `package.json`/Make/etc. scripts and reject install/mutate/watch/service bodies before offering them.
- **Safe-command ranking** — confidence → tier (typecheck/build → lint → unit → full → e2e) → value → cost; PM from lockfiles, confidence raised by config files.
- **Command-safety classifier** — unwrap `sudo`/`npx`/`poetry run`/…, reject installers/mutators/watch, identify probe kind.
- **Check evidence retains ownership and freshness** — ordinary coder output must not disappear because it contains an internal-looking substring such as `EXIT:`; orchestration belongs to its producing call/transport owner. A cached red gate whose freshness is no longer established reaches the completion judge as historical evidence, not a current failure. Supersession requires the corresponding newer check, not a tally in an unrelated read. See [check evidence custody](check-evidence-custody.md).
- **Action-log receipts keep their native call IDs** — the shared reasoner-facing action log carries JSON-quoted IDs on call/result frames, so grouped or out-of-order results remain attributable. Original call/result order, arguments and result bytes are unchanged; missing IDs are not inferred. This is provenance serialization, not a new judgment or steering policy. Refusal, unapplied-edit and landed-write facts require the producing lowering's positional typed record and paired call receipt, not a marker quoted by stdout; see [check evidence custody](check-evidence-custody.md).
- **A closed-question judge's unbounded evidence rides as composed blocks, never inside a protected message** — the floor can reduce only whole unprotected turns, so an action log or session inside the SYSTEM message or the active USER message is irreducible and the body dies at the wire (`Measured input cannot fit the context window without losing protected input`, twice per judge: the reasoning-on pass and its retry). phi4 A11 (16,384 window, 8,192 reserve): the steer-diagnostic judge (`_diagnostic_action_verdict`, whole session as `{{GROUNDING}}` in the system message, 17.7k est. tokens, `turns_dropped: 0`) and the completion judge (`judge_satisfaction`, action log in the active user message, 22.2k est. tokens) both failed; the steer was withheld as `UNDECIDABLE` and the coder got the generic "not yet verified" — a verdict nobody read. The record now goes through the shared lossless `evidencesummary.blocks` splitter (`loop._evidence_blocks` delegates to it) (whole lines, `"".join(blocks) == text`) as `evidence_blocks` — the composed-call contract `summarize`/`_judge_completion` already had — and the floor drops the OLDEST blocks first behind a `⟦ctx:compacted⟧` label; what stays differs by seat. Completion judge: the task and the question ride in the final (pinned) message and always stay, the current-disk-files message sits just before it and is shed after the older record, and the newest actions outlast the oldest. Steer-diagnostic and negative-diagnosis seats: the question lives in the protected system message and a closing "answer the question" turn; the task and session are only EVIDENCE blocks there, so the oldest of them — task included — can be shed, labelled by the `⟦ctx:compacted⟧` digest note. Each seat's pointer text is true of its own layout (`composed_evidence_intro_system`, `steer_diagnostic_grounding_above`, `negative_diagnosis_log_above`, `satisfaction_user_composed`). Seats converted: steer-diagnostic grounding, completion judge, negative-diagnosis support (its action log), the explicitly enabled step critic, and the living-plan tail proposal. The evidence-selection owner only folds repeated actions; it never replaces distinct tool results with a model-written summary. Step and tail questions retain their active step/task scope while their history uses the same producer-labelled evidence blocks. Not a C13 regression: the same error fired on 2026-10-10 (before `483a0ea1`); C13's file-facts block adds one line per file. The confirm/exact-form questions retain their existing bounded-input layouts.
- **Timeout-bounded, lossless probe runner** — the harness runs ONE composed script into a temporary spool outside the workspace, returns it in checked pages over ordinary asynchronous tool turns, and cria replays bytes through the existing parsers only after the declared size and SHA-256 verify. Checker, cleanup and survey extents and real section-header offsets are producer-declared; quoted report/header text inside checker output establishes no private section. Unframed history stays unknown rather than using a marker fallback. Within that same gate, a detached supervisor owns native execution, cleanup of exclusively allocated private auxiliary scratch, and a fresh original-workspace survey before evidence return. Authenticated allocation credentials and descriptor identities authorize retries and disposal; temporal absence never authorizes deleting original-workspace files. Native build outputs remain project-owned. Native `TMPDIR` (including its absence) is inherited unchanged; only the dedicated `CTX_PROBE_AUX` allocation and authored Python compiler bytecache prefix select private scratch. Actual private removals, failures or unknown cleanup and original-workspace scope are disclosed separately from native checker output. Historical reconstruction retains the originating request's workspace alongside its immutable per-transport command facts; a foreign receipt or unknown/evicted origin cannot authenticate its own scope. No cleanup mutation rides on a later coder read, write or refusal. Incomplete transport is `UNKNOWN`, never clean; cria never opens the remote path. The invariant harness-side programs (page reader + workspace survey) are written ONCE per session as a content-addressed helper in the harness's own temp dir and invoked by name; pages are zlib-packed when the harness's python3 has zlib (`enc` field; offset/total/sha256 stay over the raw spool). A vanished helper answers `helper-gone` → terminal `UNKNOWN`, and the session re-installs it for the next gate.
- **Diagnostic parsers** — rustc/cargo, tsc, ESLint, pytest, and generic `file:line` → structured findings + a one-line summary; **error-class only** (unused-import/style advisories don't block).
- **Ground-truth completion gate** — on a "done" claim, run the floor + top probe + top TEST probe; broken code or failing tests block, and the exact `file:line` becomes the re-prompt. A first gate that only bootstraps the workspace survey is not fresh evidence: cria plans one new gate from that survey before completion. An already-surveyed workspace with no applicable probe, or a harness with no shell, keeps the bounded safe exit. The survey that rides a gate also fetches every file the completion judge will be handed (`groundtruth.want_judge_bodies`, called from `probegate.plan_gate`): a turn that reads the deliverables beside a native command leaves every sibling read's body unprovable, and the judge refused finished work over "NAMED, NOT SHOWN: README.md, config.toml" (found twice by real Codex cells). The gate also reads the executor-side completion marks of the session's unreplied writes before and after the checks and holds completion with a typed notice when a write is unsettled (`prompts/gate_unsettled_writes.txt`, bounded by `MAX_COMPLETION_CHECKS`; the notice says whether the writer's process is gone (`dead`: read from its own start record and `/proc`, never a signal, and not proof the write did not land), still running, or unknown; a landed same-file rewrite supersedes a dead earlier write; mechanism in [check-evidence-custody.md](check-evidence-custody.md)).
- **Build/source/test participation evidence** — one three-valued schema reads the actual gate event plus `wsview` manifest/config declarations through adapters for all nine discovery ecosystems; exact supporting tool lines reach completion judges, and unsupported source/test reach stays unknown rather than becoming pass/zero.
- **Changed-a-file leg** — a coder turn ends only if it actually modified a file on disk this task.

## Reasoned guidance — the reasoner as the stuck-loop response

- **Reasoner role routing** — a separate cheap local reasoner role, routable with failover: per-role endpoints, retry-same-once on a timeout, and a chain WALK when a call fails (`chainendpoint.ChainEndpoint`, wired by `Router.route` / `Router.endpoint_for`): a refused connection, 502/503/504, a timeout after its retry, 404, 500 or exhausted 429s moves the call to the next resolvable role of its chain **on a different endpoint** (two roles on one server are not a chain). Lanes: coder → `[failover].coding` (a proxied turn: its task type's chain), reasoner → `reasoning`, classifier → `classification`, compactor → `compaction`. A stream walks only before its first frame; a typed capacity/protocol failure, a 400/413/422 and a 200 that is not a completion do not walk; the target re-fits the final wire to ITS window and the walk is a `failover.walk` event (exhaustion: `failover.exhausted`, then the ordinary truthful error). Design, what walks and what does not, and the limits (a walked hop gets ITS OWN role's temperature/top_k/reasoning dialect/instruction placement: `Role.apply` records the pre-role body as the wire-stripped hint `bodykeys.ROLE_ORIGIN` and `ChainEndpoint._body_for` restores it and applies the standby `Role`; image-bound bodies never walk, so the coder observer's role signature is never re-bound; a `cli` backend cannot hold a loop role — `config` refuses it at load, use it as an escalation role under another name in a chain): [decision-log.md](decision-log.md#architecture-decisions).
- **Plan-first (gather-and-plan; explicit experimental opt-in only)** — OFF by default, including L5; when explicitly enabled, on a new task the reasoner is engaged first with a read-only tool subset (`list_dir`, `grep_files`, `read_file`, `web_fetch`, `web_search`), loops to inspect the repo + fetch docs, then emits a small-step plan grounded in what it found; pinned atop the coder's context, cached per task. The repo tools answer from the workspace view (`cria/wsview.py`), not from cria's own disk; there is no shell here at all.
- **Reasoned redirect** — when a loop guard fires, the reasoner authors exactly one next action (or `ON_TRACK`) from FRESH ground truth: the repeated failing action + its output, the pinned task, the touched files as the harness last reported them (`groundtruth`, via the workspace view), and the dirty-only lint probe. Checker evidence stays in its exact, separately marked ground-truth channel; the author never quotes or paraphrases it into the action. Before delivery, one focused whole-action judgment receives that action and the current diagnostic as separate inputs, plus exact refused coordinates and the same task/workspace evidence as the author; there is no second lexical per-token veto over incidental filenames. A directive ruled to dictate code — native classifier DICTATES, or on the legacy reasoner path DICTATES over code cria never observed — is withheld whole, never hollowed and never restated (`loop.steer_dictated_code` delivered=False, refused_by `dictated_code`); the caller's own floor applies. The blind rewriter that used to restate it was removed after its delivered restatements were measured inventing requirements or drifting purpose (4 of 5 in a 102-steer census; run07 0038→0039 turned a `javap` signature inspection into "Design a parser that counts every skip reason separately"), while paired coder continuations lost no inspection or first-action quality with it withheld. Known cost: an occasional useful restatement (2026-08-23 0317→0319) is no longer delivered. A legacy DICTATES over observed code is a quote and ships as authored. A write after the cited gate withholds the now-stale action. The raw checker result or canned directive is the fallback only when the author gave no usable answer (none, cut, ruminating, unreadable, or vetted away — including a withheld dictation) or no reasoner is available; a settled `ON_TRACK` delivers nothing and is logged as `loop.steer_on_track` / `loop.stalled_on_track`.
- **Completion critic** — one reasoner call reviews the work (task + recent tool outputs + fresh lint/test results, tests-that-didn't-run counted as not-passing) and re-prompts while its flagged issues keep changing, stopping when they repeat. A positive verdict is deterministically barred when the authoritative gate has not proved test participation and a focused reasoner judgment says the task requires executed tests. For a proven test run, a task-specific end-to-end CLI/tool requirement triggers a focused inspection only when that same gate survey freshly captured mapped bytes for the selected test source: it must invoke that CLI/tool and check output or exit status, not merely call its upstream service; a missing mapping/source, negative, or undecidable answer bars completion. When the gate's own runner collected nothing (test support absent) and the task names a run, one more focused question puts the coder's own recorded shell runs (command, exit status, output head; never cria's gate command) beside the task and asks WHICH run is the required test; the completion is released only when the named run exists and did not exit non-zero, and an unreadable answer, no run or a failed run keeps the block. Non-test tasks and proven non-E2E tests pass untouched. A negative verdict keeps completion fail-closed, but its coder-facing diagnosis has a typed claim kind, an exact task quote, and an exact quote from one named current evidence source. Code verifies those quotes and all workspace state through `wsview`; a task-named file's proven absence is deterministic and directs the next turn to create that exact file without choosing its contents, while other task/evidence relationships get at most one focused `SUPPORTED` / `UNSUPPORTED` / `UNDECIDABLE` judgment. Unsupported or undecidable prose is suppressed without turning the verdict into approval. Missing a whole file and missing required content inside an existing file are distinct types, and a requested report's documented risks are not silently promoted into requirements.
- **Shared critic response reading (historical F37 → F33)** — whole-task and optional step critics use one call/cleanup/parse/truncation/negative-only recovery pipeline. Cleanup uses the effective reasoning-off call role, so a leaked pre-`</think>` deliberation cannot override the actual answer. The shared JSON parser protects complete object literals while recognizing outside protocol wrappers; quoted think markers, braces, escapes and fences remain payload bytes, not framing. Verdict keys, raw verifier text, phase events, caller retries, read-only inspection and composed evidence remain distinct. A reasoning-off retry withdraws inspection tools, not already available harness file evidence; file seeding retains its workspace origin independently of tool availability. A cut reply is not a verdict; recovery never approves from private reasoning. No successful verdict incurs another judge call.
- **Honest incompletion** — when the gate gives up with issues unresolved, its verdict is written into the turn's FINAL message, not just a log line.
