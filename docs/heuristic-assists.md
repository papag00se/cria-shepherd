# Heuristic Assists — implemented in cria

A terse index of the assists cria **actually implements** today, in five families. One line each. Design rationale and code pointers live in [local-coder-massaging.md](local-coder-massaging.md); the conceptual overview in [shephard.md](shephard.md); still-unbuilt levers in [port-fidelity-audit.md](audits/port-fidelity-audit.md).

## Nudges — directives/refusals the model sees

- **Repetition guard** — same tool + args 3× in-window → run the repo's checks, then a grounded reasoner redirect (canned fallback).
- **Wheel-spin guard** — same file rewritten 5× in-window → probe + steer. Only writes that LANDED count: a refusal or an edit that did not apply (`⟦ctx:edit⟧` result) is taken back at the next turn, and the N calls of one turn count once when sent and are judged on what landed at the next acting turn (`GuardState.spin_recheck`) — phi4 A4: nine refused edits in one reply read as "rewritten 5 times". The edit-failure escalation ("failed N times — STOP editing") likewise counts earlier TURNS only; later failures to one file inside the same turn say they did not apply and refer to the first.
- **Rumination guard** — a mid-generation self-doubt spiral OR reasoning over the token budget → abort the stream and re-prompt.
- **Output-truncation guard** — a `write_file` cut off at the output-token cap → refuse the partial, steer to incremental `edit_file`.
- **No-tools (LEG0) nudge** — a no-tool-call "done"/prose turn → act-first nudge (once per step), then the gate.
- **Measured facts on an unnamed gap** — when the completion check is NOT satisfied but names no gap (typed diagnosis suppressed), `done_no_named_gap` is followed by what cria measured, as facts only (`loop._measured_gap_facts`): which files the coder READ are unchanged/changed on disk (size+mtime) since the first complete survey of the session (abstains without a complete baseline and a complete current listing), and whether the last reply held N fenced code blocks and no call (the `unexecuted_write` fence parse). No file or tool is named as a thing to do. The constant alone was the same bytes for twelve cycles in the A1 run.
- **Absence is a fact, not a label** — a negative diagnosis citing `workspace_absence`, over a subject that is a whole token of the EXACT task quote and that wsview proves absent, is canonicalised to `missing_file` whatever kind the judge chose (`loop.negative_diagnosis_canonicalised`); and when the plan-OFF done-critic is not satisfied with NO usable diagnosis, the plan-ON deliverable observer (`observe_task_missing_file`, complete+current survey only) is asked once and its typed `missing_file` answer replaces the unnamed gap. A1 call 0021 (exact quote, `missing_content` label) was suppressed for the label.
- **Exact form is measured from the file, then extracted, then compared by arithmetic** — a `satisfied` verdict is committed before the judge compares anything, and the escaped-JSON layout hides a file's byte-level shape (C13-C: 29 bytes approved for a task requiring 30, the final line break missing, 3/3 on replay, and again with counts appended to the broad prompt). `loop._written_file_facts` counts the CURRENT content of each file the session wrote or edited (only calls that returned a result and were not refused): the workspace view's body when usable and nothing that writes has run since its survey, else the newest whole write to that path — in BOTH cases only when no later edit/patch/harness Edit/writing shell could have touched the file (a native patch teaches the view nothing, so its body is the pre-edit file) — otherwise nothing is stated (a veto the disk can settle is settled by the disk, never by a stale write; command and path strings are never measured). On an approving verdict `loop._exact_form_blocks_completion` asks ONE focused extraction question (`exact_form_requirement`): does the task fix a counted file's exact byte size or whether it ends with a line break? The judge only extracts (quote, file, figure); cria checks the quote is in the task, the file is a counted one (paths normalised), and that the FIGURE is fixed by the quote itself — a byte count and an ending claim are each confirmed by one more focused question about the quote alone (does it fix an EXACT size in bytes — not a bound, not words/lines, not a value inside a file — and which number?) — then COMPARES by arithmetic. One re-ask on an unreadable answer before failing closed. A mismatch holds the approval and the coder sees only cria's measured lines (`exact_form_unmet`); an ungrounded or empty extraction cannot veto; an unreadable answer fails closed. A first design that let the judge decide `contradicted` itself blocked 4 of 62 real approvals (all false positives) and is retired. A10 (01a12bca) never reached an approval.
- **The deliverable observer asks one coherent question** — its `verdict` tool carries its OWN field descriptions (`verifytools.verdict_tool(key, "observation")`: `missing_file` true = a task-named file is absent, every empty field is the empty string, never the word "empty"), it is handed the complete workspace listing (`groundtruth.workspace_inventory`, which withholds its "not listed = does not exist" clause itself when the survey is partial/folded/overtaken), and it is asked to check each task-named path as `present`/`absent` before the JSON, with the task quote being just the path as the task writes it. phi4 on the A2 call-0008 body: `false` + `"empty"` literals 2/2 before; `true`, subject `REVIEW.md` 2/2 after.
- **Remediation nonwrite follow-up** — only after a typed missing-file remediation reached the coder and its own supported read/inspection tool result returned → one additive reminder that inspection is not completion; unknown or potentially mutating actions are silent, and it never selects contents, issues a write, or settles the remediation.
- **Periodic gate** — every 15 acting coder turns → insert the repo's fresh check results as ground truth.
- **Declared JS runner reset** — after a non-zero configured `package.json` test runner result, deterministic manifest/exit/workspace facts go to a one-shot reasoner judgment; only `RESET` pins the next turn to that declared runner and the task-confirmed no-`node_modules` contract, while preserving the checker’s own output. It does not inspect failure prose or action keywords, and Go/Ruby never enter this path.
- **Go module-state reset** — after a non-zero `go test -mod=readonly` result, the selected test command, exit state, and exact checker output go to a one-shot reasoner judgment; only `REANCHOR` asks the coder to inspect the current module manifest before another dependency edit. It matches typed probe facts, not error wording, package names, or proposed actions; Ruby/JS and green Go checks are silent.
- **Search exact-repeat guard** — an identical/re-worded search this session → HTTP 400 before the network hit.
- **Domain-fetch steer** — a search naming a bare domain → "fetch `https://<domain>` directly" hint.
- **Fetch exact-repeat guard** — an identical external `web_fetch` (url + find + cursor) this session → HTTP 400; internal hosts exempt.
- **Failing-fetch guard** — 3 consecutive non-2xx external fetches → a "stop guessing URLs" nudge; localhost exempt.
- **Direct root-deletion backstop** — refuse narrowly recognized direct `rm` recursive-root / `find / … -delete` shell commands even with unrestricted directory permission; tokenize to avoid echo/grep/comments, and abstain on heredocs or unparseable shell. This does not inspect invoked programs or computed targets.
- **Inference-free filesystem-mutation review** — synthetic writes and exact edits analyze complete candidate source, without a model. Shared path/resource facts and `dirguard` boundary rules produce `PROVEN` (block), `POSSIBLE`/`UNKNOWN` (log only), or `WITHIN_SCOPE` findings. Python has AST/dataflow analysis; JS/TS, Go, Rust, JVM, .NET, PHP, Ruby and Elixir have narrower lexical/API-contract adapters. Destruction-only adapters additionally cover closed-expression contracts in C, C++, Swift, Objective-C, Dart, Lua, Perl, R, Julia and PowerShell; that is not broader build/test support. A universal advisory scan also surfaces unresolved destructive-looking calls; it never blocks on spelling. Missing source and unsupported constructs remain unverified. Refused edits are bound to workstation-side bytes; drift requests a fresh read. The exact recovered `orders-api-py` source now blocks through production lowering without a judge or executing the source. Not containment or full language coverage: see [coverage, confidence and limits](cleanup-safety.md).
- **Shared-install guard** — a package install whose destination is the user/system environment (`pip install`, `npm -g`, `gem`/`cargo`/`go install`, `apt`/`brew`) → refused with the in-project venv route; project-local installs (`npm install`, `composer require`, `cargo add`) pass untouched.
- **Missing-dependency note** — beside the latest real loader/compiler failure, quote the exact unresolved package and distinguish an undeclared dependency from an invalid package name. For Go, the note explicitly withholds `go get` as a remedy until authoritative package source establishes that the import path exists.
- **Dependency refusal events** — preserve session-scoped raw resolver coordinates, tool provenance, and event order across npm/pnpm/Yarn/Bun, pip/uv/Poetry, Cargo, Go, Maven/Gradle, NuGet, Composer, RubyGems/Bundler, and Hex/Mix; a later observable exact success supersedes the current refusal without deleting its history. Exact-name matching only triggers the existing whole-action reasoner judgment; it never vetoes semantically. See [dependency refusal events](refusal-events.md).

## Massages — silent output repair so the harness accepts it

- **write_file / edit_file ↔ shell round-trip** — lowered to a byte-exact base64 heredoc write; the recorded shell call re-presented as the original tool.
- **Leaked-call recovery** — tool calls emitted as text (Hermes `<tool_call>`, XML `<function=…>`, Gemma-fable `<|tool_call>…`) → real calls; Gemma `<|channel>` thinking stripped.
- **Fenced-envelope call recovery** — in the same chain (`massage.recover_leaked_tool_calls`): a call-less turn whose first fenced block (text-tagged `plaintext`/`text`/untagged fences aside) is a single un-nested call object, name on THAT request's menu and arguments schema-admitted, not cut at the output cap → ONLY that first call is promoted; `content` keeps the prose before the fence verbatim and everything from the fence on (later calls, fabricated results, completion claims) is not forwarded, logged as `dropped_chars`/`later_envelopes` on `massage.fenced_call_recovered` (`massage.fenced_call_refused` carries the reason). **A call object is a SHAPE, not key names**: exactly two keys, one string (the tool) and one object (its arguments) — `{name, arguments}`, `{action, parameters}`, `{tool_call, arguments}`, `{action, args}` all parse, and the menu then decides whether the string names a tool (three keys — a schema echo, a `package.json` — never parse). **A code fence before the call is admitted iff the call's string argument is whitespace-normalised IDENTICAL to one of those fences** (≥80 chars; the draft-then-write reply), and refused when any preceding fence is a JSON object (a result/echo). Measured: 196 of 44,234 captured replies, all phi4 (+15 more recovered by the shape/identity extension, all phi4, 0 on ten other models); fabricated sessions, unrelated drafts and schema echoes are refused by the leader rule. Level 1; L0 untouched.
- **Pasted-file → write recovery** (loop, `Loop._recover_text_write`, the shared coder turn — L4+ because it needs the judge and the workspace view the massage chain lacks) — a call-less turn that typed a WHOLE file into chat under the file's name (phi4 cannot reliably emit a tool call whose argument holds newlines) becomes that file's `write_file`. The first fenced block ≥ `UNEXECUTED_WRITE_LINES` whose directly-preceding line names exactly one path; the path must resolve to ONE workspace file (unique over a complete listing) or be a new file the task text itself contains; not a quote of anything the coder was shown, not already the file's content; one focused reasoner question (`WHOLE_FILE` / `OTHER`, exact positive token, anything else refuses) settles whole-vs-excerpt (a 5-line `<dependency>` excerpt for pom.xml is never a file). Only that block is written, with the model's own bytes; the prose before it is kept, the tail is dropped and logged; the call is replayed through the same lowering passes as a native one. Every refusal is the `unexecuted_write` nudge, as before. Events: `massage.text_write_recovered`, `loop.text_write_judged`, `loop.text_write_refused`. **The nudge that follows a refusal claims only what is true (K4)**: a block the judge ruled `OTHER` (`PlanSession.pasted_block_other`) draws no `unexecuted_write` nudge (phi4 A4 0079→0080: an excerpt and a draft were answered with "the file's contents… send again", then a fabricated whole pom.xml); a block the model bound to exactly one path names that path (`unexecuted_write_nudge_path`); any other block (48% of the 293 captured firings) is told a block of code was sent as text and that nothing in it reached the disk — no file is claimed.
- **An empty `edit_file` old_string is refused as what it is** — `old_string: ""` names no text (it "matched" len+1 boundaries and was answered `matches 191 places — add surrounding lines`, phi4 A4 0024). `writeproxy` refuses it at the lowering as a call that did not run (`edit_empty_old_string.txt`): nothing changed, name the text to replace, or `write_file` for the whole file. cria authors no content; edit_file has no whole-file contract.
- **A write to a file never seen, and a call not run, are said** — (1) `write_file` naming an EXISTING file (the workspace view proves it) where the conversation holds no WHOLE read of it (a ranged/prefix read, a read whose result the harness compacted away, and the durable read ledger do not count — phi4 A4 0047: lines 1-8 of 29, then overwritten), no whole write of it by the coder, and no shell result of a plain `cat FILE` (`loop._prints_whole_file`; any other command that merely names the path abstains: no credit) (`loop.unread_target_fact`), is ANSWERED at the write lowering with the file itself: the harness runs a read of the path the coder named, and the result for the coder's own `write_file` call is the measured fact (`<path> already exists on disk (N bytes) and no read of it has been recorded this session…`), `This write_file call was not run… the file is unchanged`, a `⟦ctx:read-instead⟧` line, and the file's bytes exactly as read (`writeproxy._read_in_place_of_write`; re-presented as the coder's `write_file`; the answer carries the `denial` did-not-run mark (so every "did this write land?" owner — `_extract_writes`, contextfloor, focustrim's supersede rule, `_failed_edit_ids` — reads it as the never-run write it is, and its content is never squashed) while `loop._extract_reads` checks the read marker FIRST and counts it as a read, so the next write to that path proceeds — the hold lifts exactly when the file has been seen, never on a count; the once-per-path pass of B3 is gone: it let A3 overwrite the seed `Importer.java` and `pom.xml` unread). A file over one read's limit (or unreadable) gets the whole-read owner's steer to read in ranges and records no read until one returns. A harness-native `write_file` (not lowered) is untouched. The shell-read credit is for `cat` only. Decided on that structure, never on what the content looks like; a new file, a read file and an unsurveyed workspace are untouched; `edit_file` stays with the blind-edit grounding. (2) A fenced call `massage` refuses to promote (`prefix_fence`/`nested`/`off_menu`/`inadmissible`) now rides out as `bodykeys.FENCED_REFUSED`; the loop says which call did not run and the rule that stopped it (plus the same measured fact when it names an unread existing file) in the nudge after the call-less reply, and the pasted-file recovery's `unread_existing_file` refusal rides on its nudge. Facts only; no tool or content is chosen for the coder.
- **A landed edit repeats itself** (S2 echo, `writeproxy._ECHO_DEF` → `render_edit_echo`, `prompts/edit_echo_repeat.txt`) — when the replacement is longer than the old_string AND the lines directly after it (blank lines skipped) read, whitespace-collapsed, the same as one unbroken stretch of the replacement (≥ 2 lines, ≥ 2 distinct, alphanumeric), the echo states the counts and the line ranges. Facts only: no directive, no verdict on intent. It exists because a coder anchors old_string on a member's FIRST line and sends the whole member as new_string — that replaces one line and leaves the old body underneath (phi4/Java A8, A10, A11). Measured on the 286 replayed-and-verified landed edits in the capture corpus (123 with a longer replacement): 8 fire, every one a real duplicate; the fuzzy variant (line similarity ≥ 0.7) fired 13 and two were legitimate neighbours (an import list, a sibling test), so it was refused. NOT covered: a leftover whose lines were *altered* (A11 `knownSkus`/`worker`, a rewritten body over the old one) — exact repetition is the only measure with no false positives here; the judged extension (one focused question, after a ≥3-line replacement of a 1-line old_string) is the open follow-up. The edit executor also serialises concurrent edits and never leaves a half-written file: it resolves the path (`realpath`), takes an exclusive `flock` on the target's directory (nothing is created in the tree; `write_file` takes the same lock), and swaps the new bytes in with a temp file beside the target. A symlink is therefore written THROUGH (the link survives); a file with more than one hard link is written in place under the lock (a swap would split the links). The swap keeps the mode and tries to keep owner/group (`chown`, best effort); ACLs and extended attributes are not carried, and a swapped file gets a new inode. An unwritable directory is reported as a plain "could not be written" result, not a traceback. A batch of edits to one file also applies in the coder's CALL order: each queued edit carries its predecessors' indexes and waits (outside the lock, at most `EDIT_SEQ_WAIT_SECONDS` = 5 s — under the ~10 s a harness lets an unbudgeted command run) for their done-marks under `$TMPDIR/.cria-edits-<per-translation token>`, removed by the group's last edit; a predecessor that never arrives is not waited for further and the result says the edit ran early. The repeat sentence says "blank lines aside" because blank lines are skipped when matching.
- **A whole-file write that would gut a file the coder read: a FRAGMENT is judged and held; a REMOVAL lands with facts** (`Loop.shrinking_write_check` → `writeproxy._held_shrinking_write`, the write lowering) — H2. Both are measured by `loop.shrink_measure` over a file cria holds the text of (a read or the coder's own write; unknown = silence) with ≥ 8 non-blank lines.
  - **FRAGMENT** — candidate ≤ half the file's non-blank lines AND repeats < half its distinct lines (phi4 A4: a 190-char `<dependencies>` excerpt as `write_file pom.xml` over the 28-line POM; A3: a stub over `Importer.java`; 16 of 1,156 corpus writes). WHAT IT IS goes to the pasted-file recovery's closed question (`WHOLE_FILE` / `OTHER`, `loop.whole_file_ruling`; prompts `write_call_judge*.txt`). Only a clear `WHOLE_FILE` (remembered per path+content hash) lets it run; anything else holds it: the call is not run (`denial` mark via `_refusal_command`), the result states the measured sizes/lines, how many lines would be removed and the first, and the least-indented removed block openers; the rejected payload rides after it; `edit_file` is named only when the menu has it. A hold is not remembered (an identical repeat is asked again; at temperature 0 a false `OTHER` holds identical content indefinitely; the coder's outs are `edit_file`, a shell command, or content that keeps more of the file). Bound to the bytes measured: the lowered command refuses only while the file on disk still equals them. Needs no survey baseline — the question is about the content, whoever made the file. Counts are true units (`repeats K of the file's D distinct non-blank lines`; R = multiset difference, a lower bound).
  - **REMOVAL** (cycle 12, phi4 A9: a 69-line rewrite of the 114-non-blank-line `Importer.java` lost `summarize`/`Summary`/`totals`/`main`; it slipped under the fragment test because 69 > 57) — the write removes ≥ half the file's non-blank lines but the candidate is longer than half. It is **never held and never asked**: the candidate IS a whole file, so the honest answer to the closed question is `WHOLE_FILE`, and a line threshold must not make that semantic call (principle 8). The write lands and its own result gets the measured facts appended (`write_shrink_facts.txt` `removed_landed` + `openers`): `removed at least R of the file's N non-blank lines` and the up-to-12 least-indented removed lines that open a block (next line indented deeper), in file order — indentation, not vocabulary, so a definition/class/loop header in any language and never the imports. Facts only, never a directive; printed (one `⟦ctx:removal⟧` line after `⟦ctx:wrote⟧`, re-rendered by `represent_inbound` after the `Wrote <path>` confirmation, which otherwise replaces the whole raw result) only if the write landed and the file on disk still equals the bytes measured. Only for a file in `PlanSession.first_survey_files` (listed by the FIRST survey to land — folded or incomplete included, a listed file is proven present — minus files a landed coder `write_file` created before it rode back): principle 2 protects progress the coder did not make, and a deliverable the coder created (REVIEW.md) is rewritten whole freely. No first survey = silence. Corpus: 102 of 1,182 big-file writes (8.6%) remove ≥ half the lines; 49 (4.1%) once coder-created files are exempt (approximated by "first corpus appearance was a coder write"; `~/.cria/validation/phi4-java-focused-loop/h2_removal_rate.py`).
  - **Measured live behaviour (phi4, 2026-10-11, temperature 0, `h2-fragment-write.md`): the judge answered `OTHER` on 22 of 22 runs of 11 legitimate shrinking rewrites and held all 14 runs of the fragments** — it does not discriminate honest rewrites from fragments, so for this model a FRAGMENT-class rewrite is effectively held until `edit_file`, more-of-the-file content, or the shell. That was accepted for the 1.4% fragment class and is exactly why the 4.1% removal class is facts, not a hold. No reasoner, assists off (L<5) or an unknown file: untouched. Events: `loop.write_shrink_judged`, `writeproxy.write_shrink_held`, `loop.write_removal_facts`, `writeproxy.write_removal_facts`.
- **Native tool-call sentinel strip** — `<|tool_call_start|>…<|tool_call_end|>` pairs + orphans stripped from content (templates that leak their own call sentinels).
- **Reasoning-channel call recovery** — a COMPLETE call the model left in `reasoning_content` (the one channel llama.cpp's parser never reads) → a real call. Only when the turn is already lost (no text, no `tool_calls`), the call is terminal and unfenced, every argument is a literal the model typed, and the name + required args are on the request's own menu. Measured 2026-08-03: 80 lost replies across 127 sessions, 68 recovered; the worst-affected model lost 10.7% of its coder turns this way.
- **Shell-name rewrite** — `ls`/`cat`/`grep`/`git`/… emitted as tool names → proper `shell` calls (full alias table).
- **exec_command array fix** — `cmd` as `["bash","-lc",…]` → routed to `shell`.
- **Shell-args normalization** — a string command wrapped to `[bash,-lc,cmd]`; a double-wrapped array unwrapped.
- **read_file normalization** — `read_file(path, range)` → a `shell` `cat`/`sed`.
- **edit_file → apply_patch** — a find/replace → a native `apply_patch` Update hunk (when the harness runs apply_patch).
- **Tool-argument normalization** — string→JSON parse, dict passthrough, `{value}` wrap; `{function:{…}}` vs `{name,args}` unified.
- **Fenced-JSON tolerance** — tool args wrapped in ``` fences → extracted.
- **Malformed-JSON repair** — botched `write_file` args (raw newlines/quotes) → path + content recovered.
- **Missing-content refusal** — a `write_file` whose required `content` is absent or null → refused, not lowered as an empty write (the byte-exact write truncated a working file to zero and reported success); an intentional empty string still writes. Sibling of the `new_string` refusal on the edit path.
- **Double-escaped-newline repair** — a file written as one physical line with literal `\n` → decoded.
- **apply_patch normalize** — unified diff → native; missing `+`/`-`/space prefixes repaired; hunk headers collapsed; multiple wrappers merged; a pure Add-File patch → a whole-file write.
- **Malformed-tool-call recovery** (re-prompt) — an unparseable `<tool_call>` → re-prompted to re-issue cleanly, steering multi-line work to `write_file`.
- **Failed-patch → rewrite** (re-prompt) — a failed apply_patch forces a whole-file `write_file`, released the instant the truncation guard fires.

## Context shaping — what the model sees and how much

- **Own concise coder prompt** — cria's `coder_system.txt` leads, replacing the harness's bloated system prompt.
- **Tool-menu focus** — curate to the coding-essential tools; synthesize lean `read_file`/`list_dir`/`write_file`/`edit_file`/`web_fetch`/`web_search`.
- **Tool cheat-sheet** — plain-language per-tool usage generated from the live menu, carried into cria's system message.
- **Window auto-detect + derived budget** — read real `n_ctx` from `/props`; budget = window − output reserve.
- **Real-token calibration** — a rise-fast/fall-slow EWMA learns the model's chars→token ratio (≈1.8× → 3.5×). With a discovered local template, the final rendered prompt is also tokenized before sending; measured overflow refits the original input through the single floor before capture/POST, while an unchanged irreducible overflow is refused. Unknown measurement stays unknown; L0 is untouched.
- **content_reduce** — MIME-aware lossless-first reduction of an oversized tool output (HTML→text, JSON minify) before it blows the window.
- **Self-compaction** — token-triggered: roll the old transcript middle into a retrospective `⟦ctx:rollup⟧`, keeping the tail verbatim and giving the writer the pinned original task. Three independent fail-closed judgments — no forward plan (asked per SENTENCE: `STATE`, or a `PLAN`-looking sentence the original task already states, answered `TASK`; a whole-candidate PLAN verdict rejected every task restatement), `PRESERVES` for full task scope, and `FAITHFUL` for fidelity to transcript/disk/check facts (including decisive negative evidence). Rejection retains verbatim history and suppresses a retry until a new token band accumulates. Rare rollup refolds pass through the same gate.
- **Reducible internal evidence** — compactor, briefing-validator, and steer-author transcripts ride as independently reducible evidence turns between a small introduction and the final active question. With no pressure their bytes are unchanged; under pressure the single context floor can fold/drop whole evidence blocks with its existing labelled stand-in instead of knowingly sending an irreducible oversized two-message body. The inspecting author's task/current-facts/question packet uses the existing exact wire pin, so a later forced-answer closer cannot make it droppable. This restores answer capacity and retention; it does not establish better reasoner judgment.
- **Rejected harness handoff keeps a tool ledger** (`selfcompact.work_ledger`, appended by `server._harden_compaction_reply` only when no model prose survived) — phi4/Java A10 rejected 29 of 29 briefings (PLAN on requirement restatements and real next-steps; NARROWS on briefings listing all six deliverables) and every later window held only a file listing. The prose is what fabricates progress, so it stays rejected; the window now also gets a deterministic, labelled record of what the tools did — per write: tool, path and whether the paired result confirmed it (`write_landed`); per coder shell command: the command (labelled clip at 300 chars), or `refused, did not run` when its paired result is cria's denial mark; a write whose result is neither a confirmation nor a refusal reads `no confirmation recorded`; cria's own gate/lowering commands excluded; events keep their order (identical consecutive ones get an `(N times)` prefix) and paths are workspace-relative. cria's own wording over structured fields, never a sentence of tool output, so it can carry neither a prescription nor a scope claim; the ledger leads the dropped-prose appendix, and the latest handoff turn's ledger (and only that turn's — `server._carried_ledger`; never model prose, tool output or a quoted header) is merged in so each compaction keeps the previous ones. The validators are unchanged (not a regression of 724339e7). Fixture: `tests/fixtures/c13a_a10_first_compaction_history.json`.
- **Compaction evidence owner** (`selfcompact.compaction_evidence_messages`) — one rendering for the briefing writer, the validators and the loop's self-compaction: cria's own gate calls whose raw result was filtered out as an anchor are removed (never shown as a coder action with no result), and a turn whose own digest is empty (a blanked `⟦cria⟧` status turn) is skipped rather than rendered as `assistant: `. The gate verdict, when cria holds one, still reaches the writer as the labelled checks input.
- **Model-visible usage reporting** (L1-L5; `modelview`) — the usage reported to the harness is the pre-floor size of the conversation the model is shown (gate plumbing, status turns and the harness agent prompt out; cria's coder prompt in), so cria's own plumbing cannot trigger a harness compaction while real growth still does. See [`codex-context-window.md`](codex-context-window.md#what-l1-l5-report-the-model-visible-context-pre-floor).
- **One copy of the check evidence** (`modelview.fold_evidence` → `dedup.fold_repeated_runs`, CONTEXT_FIXES and above only, identity when nothing repeats; run in `Upstream._prep` AFTER the floor decides what survives — the body is sized folded, refit unfolded if the floor touched any message, then folded last, so a pointer never outlives its copy) — the gate's findings reach the coder through three owners that never see each other (the compaction continuation that froze them, the `⟦ctx:checks⟧` result, the trailing `⟦ctx:steer⟧`) and a build tool prints its own error list more than once inside one result. ## Probes — ground truth by doing

- **Language-aware syntax floor** — `py_compile`/`node --check`/`php -l`/`ruby -c` + a TOML/strict-JSON config floor over disk files → exact `file:line`.
- **Repo probe discovery** — inventory 9 ecosystems (JS/TS, Python, Rust, Go, JVM, .NET, PHP, Ruby, Elixir) → ranked SAFE diagnostic commands. Every workspace-survey tree record, including folded-directory drain records, shares one byte bound; exhaustion closes an accepted `complete=0` survey rather than producing a count-mismatched partial inventory.
- **Package-script vetting** — read `package.json`/Make/etc. scripts and reject install/mutate/watch/service bodies before offering them.
- **Safe-command ranking** — confidence → tier (typecheck/build → lint → unit → full → e2e) → value → cost; PM from lockfiles, confidence raised by config files.
- **Command-safety classifier** — unwrap `sudo`/`npx`/`poetry run`/…, reject installers/mutators/watch, identify probe kind.
- **A closed-question judge's unbounded evidence rides as composed blocks, never inside a protected message** — the floor can reduce only whole unprotected turns, so an action log or session inside the SYSTEM message or the active USER message is irreducible and the body dies at the wire (`Measured input cannot fit the context window without losing protected input`, twice per judge: the reasoning-on pass and its retry). phi4 A11 (16,384 window, 8,192 reserve): the steer-diagnostic judge (`_diagnostic_action_verdict`, whole session as `{{GROUNDING}}` in the system message, 17.7k est. tokens, `turns_dropped: 0`) and the completion judge (`judge_satisfaction`, action log in the active user message, 22.2k est. tokens) both failed; the steer was withheld as `UNDECIDABLE` and the coder got the generic "not yet verified" — a verdict nobody read. Steer-diagnostic and negative-diagnosis seats: the question lives in the protected system message and a closing "answer the question" turn; the task and session are only EVIDENCE blocks there, so the oldest of them — task included — can be shed, labelled by the `⟦ctx:compacted⟧` digest note. ## Reasoned guidance — the reasoner as the stuck-loop response

- **Reasoner role routing** — a separate cheap local reasoner role, routable with failover (retry-same-on-timeout, chain-walk, per-role endpoints).
- **Plan-first (gather-and-plan; explicit experimental opt-in only)** — OFF by default, including L5; when explicitly enabled, on a new task the reasoner is engaged first with a read-only tool subset (`list_dir`, `grep_files`, `read_file`, `web_fetch`, `web_search`), loops to inspect the repo + fetch docs, then emits a small-step plan grounded in what it found; pinned atop the coder's context, cached per task. The repo tools answer from the workspace view (`cria/wsview.py`), not from cria's own disk; there is no shell here at all.
- **Reasoned redirect** — when a loop guard fires, the reasoner authors exactly one next action (or `ON_TRACK`) from FRESH ground truth: the repeated failing action + its output, the pinned task, the touched files as the harness last reported them (`groundtruth`, via the workspace view), and the dirty-only lint probe. Checker evidence stays in its exact, separately marked ground-truth channel; the author never quotes or paraphrases it into the action. Before delivery, one focused whole-action judgment receives that action and the current diagnostic as separate inputs, plus exact refused coordinates and the same task/workspace evidence as the author; there is no second lexical per-token veto over incidental filenames. A write after the cited gate withholds the now-stale action; the raw checker result or canned directive is the reasoner-unavailable fallback (≤6/task).
- **Completion critic** — one reasoner call reviews the work (task + recent tool outputs + fresh lint/test results, tests-that-didn't-run counted as not-passing) and re-prompts while its flagged issues keep changing, stopping when they repeat. A positive verdict is deterministically barred when the authoritative gate has not proved test participation and a focused reasoner judgment says the task requires executed tests. For a proven test run, a task-specific end-to-end CLI/tool requirement triggers a focused inspection only when that same gate survey freshly captured mapped bytes for the selected test source: it must invoke that CLI/tool and check output or exit status, not merely call its upstream service; a missing mapping/source, negative, or undecidable answer bars completion. Non-test tasks and proven non-E2E tests pass untouched. A negative verdict keeps completion fail-closed, but its coder-facing diagnosis has a typed claim kind, an exact task quote, and an exact quote from one named current evidence source. Code verifies those quotes and all workspace state through `wsview`; a task-named file's proven absence is deterministic and directs the next turn to create that exact file without choosing its contents, while other task/evidence relationships get at most one focused `SUPPORTED` / `UNSUPPORTED` / `UNDECIDABLE` judgment. Unsupported or undecidable prose is suppressed without turning the verdict into approval. Missing a whole file and missing required content inside an existing file are distinct types, and a requested report's documented risks are not silently promoted into requirements.
- **Honest incompletion** — when the gate gives up with issues unresolved, its verdict is written into the turn's FINAL message, not just a log line.
